# 总部评分导入前端对接流程

## 适用范围

本流程只处理总部核验评分。导入接口只写入 `hq_score` 和 `hq_score_item`，不写入客户评价，也不写入经销商评价。

## 1. 下载模板

- 接口：`GET /api/hq/scores/import-template`
- 权限：总部核验员、超级管理员
- 返回：Excel 文件流
- 文件名：`scores-import-template.xlsx`

模板字段全中文：

| 字段 | 说明 |
| --- | --- |
| 客户手机号 | 必填，用于匹配要评分的任务 |
| 服务环节 | 可填写：量尺服务、安装服务、熨烫服务、除尘除螨服务 |
| 总部评分 | 0 到 100 的整数 |
| 扣分原因 | 可空 |
| 评分备注 | 可空 |

兼容说明：旧模板中的 `任务ID`、`任务编号`、`任务ID/任务编号` 仍可识别。若文件同时包含任务编号和客户手机号，后端优先按任务编号匹配。

## 2. 上传导入

- 接口：`POST /api/hq/scores/import`
- 权限：总部核验员、超级管理员
- 请求类型：`multipart/form-data`
- 文件字段名：任意字段名均可，建议使用 `file`
- 支持文件：`csv`、`xls`、`xlsx`
- 返回类型：Excel 文件流
- 返回文件名：`scores-import-result.xlsx`

示例：

```http
POST /api/hq/scores/import
Content-Type: multipart/form-data
Authorization: Bearer <token>

file=<scores-import-template.xlsx>
```

## 3. 返回结果文件

导入接口无论部分成功还是部分失败，都会返回结果 Excel。前端应按 `blob` 下载并提示用户查看结果文件。

结果文件字段：

| 字段 | 说明 |
| --- | --- |
| Excel行号 | 原导入文件中的行号 |
| 客户手机号 | 原始客户手机号 |
| 匹配任务 | 成功时为实际匹配到的任务编号；失败且使用旧任务编号时显示原始任务标识 |
| 服务环节 | 原始或识别后的服务环节 |
| 总部评分 | 原始评分 |
| 扣分原因 | 原始扣分原因 |
| 评分备注 | 原始评分备注 |
| 导入结果 | `成功` 或 `失败` |
| 原因 | 成功说明或失败原因 |

响应头也会返回统计信息：

- `x-import-success-count`
- `x-import-failed-count`

## 4. 业务规则

1. 客户手机号必须存在。
2. 客户手机号 + 服务环节只匹配到一条可评分任务时才会导入。
3. 如果同一手机号同一服务环节匹配到多条任务，结果文件会返回失败原因，前端提示用户确认唯一订单；旧任务编号列可用于精确匹配。
4. 服务环节必须属于匹配到的任务。
5. 任务状态只允许：`pending_dealer_review`、`pending_hq_score`、`completed`。
6. 总部评分导入成功后，只更新核验状态，不改变任务状态。
7. 同一任务同一服务环节可重复导入，后一次会覆盖该环节原总部评分。
8. 导入不会生成客户评价，也不会生成经销商评价。
