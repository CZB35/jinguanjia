## 适用范围

本文只说明后台 `环节记录管理` 页面里的：

- `批量下载附件`

所有接口默认都挂在 `/api` 下。

## 1. 对应接口

```http
POST /attachments/batch-download
```

这个按钮不是导出接口，而是下载附件压缩包接口。

## 2. 用途

用于把选中的任务附件统一打成一个 `zip` 压缩包下载。

适合场景：

- 环节记录管理勾选 1 条或多条任务后，点击 `批量下载附件`

## 3. 请求头

```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

## 4. 请求参数

### 4.1 页面推荐传法

环节记录管理页建议直接按任务传：

```json
{
  "task_ids": [35, 36]
}
```

说明：

- 前端勾选的是任务行
- 所以后端按 `task_ids` 聚合下载最合适

### 4.2 也支持按附件传

```json
{
  "attachment_ids": [101, 102]
}
```

说明：

- 如果前端拿到的是具体附件 ID，也可以直接传 `attachment_ids`

### 4.3 两种都传

```json
{
  "task_ids": [35],
  "attachment_ids": [101]
}
```

说明：

- 后端会合并去重后统一打包

## 5. 参数校验规则

- `task_ids` 和 `attachment_ids` 不能同时为空

如果都为空，后端返回：

```text
attachment_ids和task_ids不能同时为空
```

如果所选任务没有附件，后端返回：

```text
所选任务暂无附件
```

## 6. 返回结果

返回的是压缩包文件流，不是 JSON。

返回类型：

```text
application/zip
```

文件名示例：

```text
task-attachments-20260618-153000.zip
```

## 7. 前端调用示例

```js
axios.post('/api/attachments/batch-download', {
  task_ids: selectedTaskIds
}, {
  responseType: 'blob'
})
```

## 8. 页面接法建议

1. 前端勾选任务行
2. 取勾选行里的任务 ID
3. 组装：

```json
{
  "task_ids": [35, 36]
}
```

4. 直接下载 `zip`

## 9. 一句话结论

`环节记录管理` 里的 `批量下载附件` 对应：

```http
POST /api/attachments/batch-download
```

页面建议直接传：

```json
{
  "task_ids": [任务ID数组]
}
```
