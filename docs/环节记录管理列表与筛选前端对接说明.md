# 环节记录管理列表与筛选前端对接说明

本文说明后台 `任务管理 -> 环节记录管理` 的列表接口和筛选参数。接口统一挂在 `/api` 下，需携带后台登录 token。

## 1. 主列表接口

```http
GET /api/hq/review/tasks
Authorization: Bearer <token>
```

用途：环节记录管理完整列表。该接口不会主动过滤 `待执行` 任务，适合页面主列表和与任务列表对齐数量。

响应结构：

```json
{
  "code": 0,
  "data": {
    "items": [],
    "total": 27,
    "page": 1,
    "page_size": 20
  }
}
```

## 2. 衍生列表接口

```http
GET /api/hq/review/tasks/pending-and-completed
```

只返回待评价、待总部评分、已完成类任务，会过滤待执行任务。不要用于需要和任务列表总数一致的页面。

```http
GET /api/hq/review/tasks/pending-execute-and-executing
```

只返回待执行、进行中类任务。

## 3. 分页参数

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `page` | 页码，从 1 开始 | `1` |
| `page_size` | 每页条数 | `20` |

示例：

```http
GET /api/hq/review/tasks?page=1&page_size=20
```

## 4. 筛选参数

| 参数 | 别名 | 说明 | 示例 |
| --- | --- | --- | --- |
| `task_status` | `status`、`taskStatus` | 任务状态 | `pending_dealer_review` |
| `review_status` | `reviewStatus` | 评价状态；也兼容 `pending/completed` 映射检核状态 | `pending` |
| `score_status` | `scoreStatus`、`inspection_status` | 检核状态 | `pending`、`scored` |
| `service_type` | `serviceType` | 服务环节 | `measure` |
| `task_type` | `taskType` | 三专/四专筛选 | `three_special` |
| `store_id` | `storeId` | 所属门店 ID | `1` |
| `technician_id` | `technicianId` | 服务师傅 ID | `39` |
| `mobile` | `customer_mobile`、`customerMobile`、`phone` | 客户手机号，模糊匹配 | `17796854338` |
| `customer_name` | `customerName` | 客户姓名，模糊匹配 | `森屿` |
| `technician_name` | `technicianName` | 师傅姓名，模糊匹配 | `李四` |
| `appointment_start` | `startDate`、`start_date` | 预约开始时间 | `2026-06-01 00:00:00` |
| `appointment_end` | `endDate`、`end_date` | 预约结束时间 | `2026-06-30 23:59:59` |

日期必须传完整时间格式：`YYYY-MM-DD HH:mm:ss`。只传 `YYYY-MM-DD` 会解析失败并导致筛选结果异常。

## 5. 状态取值

任务状态 `task_status`：

| 值 | 前端展示 |
| --- | --- |
| `pending_assign` | 待分派 |
| `pending_execute` | 待执行 |
| `executing` | 进行中 |
| `pending_dealer_review` | 待评价 |
| `pending_hq_score` | 已完成 |
| `completed` | 已完成 |
| `closed` | 已关闭 |

检核状态 `score_status`：

| 值 | 前端展示 |
| --- | --- |
| `pending` | 待核验 |
| `scored` | 已核验 |

评价状态 `review_status`：

| 值 | 前端展示 |
| --- | --- |
| `pending` | 待评价 |
| `reviewed` | 已评价 |

## 6. 任务类型筛选

三专/四专筛选传 `task_type`：

```http
GET /api/hq/review/tasks?task_type=three_special
GET /api/hq/review/tasks?task_type=four_special
```

兼容中文和数字：

| 前端值 | 后端含义 |
| --- | --- |
| `三专`、`3`、`three_special`、`three-special` | 三专 |
| `四专`、`4`、`four_special`、`four-special` | 四专 |

三专/四专按同一任务组已进入非待执行状态的服务环节数量判断。待分派、待执行环节不会计入三专/四专数量。

## 7. 服务环节取值

| 值 | 展示 |
| --- | --- |
| `measure` | 量尺服务 |
| `install` | 安装服务 |
| `ironing` | 熨烫服务 |
| `cleaning` | 除尘除螨服务 |

## 8. 列表字段

`items[]` 主要字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 环节记录 ID，详情接口使用它 |
| `task_id` | 任务 ID |
| `task_no` | 任务编号 |
| `task_group_no` | 任务组编号 |
| `task_type` | 任务类型 |
| `service_type` | 当前服务环节 |
| `task_status` | 任务状态 |
| `service_status` | 环节状态 |
| `review_status` | 经销商评价状态 |
| `score_status` | 总部检核状态 |
| `store_name` | 门店名称 |
| `dealer_name` | 经销商名称 |
| `technician_name` | 师傅姓名 |
| `technician_mobile` | 师傅手机号 |
| `customer_name` | 客户姓名 |
| `customer_mobile` | 客户手机号 |
| `customer_address` | 客户地址 |
| `technician_location_address` | 师傅现场定位地址，未上传则为空 |
| `appointment_time` | 预约时间 |
| `technician_score` | 总部对师傅评分，未评分为 `null` |

## 9. 请求示例

按客户手机号查：

```http
GET /api/hq/review/tasks?customer_mobile=17796854338&page=1&page_size=20
```

查待核验：

```http
GET /api/hq/review/tasks?scoreStatus=pending&page=1&page_size=20
```

查三专且排除待执行环节：

```http
GET /api/hq/review/tasks?task_type=three_special&page=1&page_size=20
```

按日期范围查：

```http
GET /api/hq/review/tasks?startDate=2026-06-01%2000:00:00&endDate=2026-06-30%2023:59:59
```

## 10. 前端注意事项

1. 环节记录管理主列表使用 `/api/hq/review/tasks`。
2. 不要把 `/pending-and-completed` 当成主列表，否则会少掉待执行任务。
3. 表格展示检核状态时用 `score_status`，不要用 `review_status`。
4. 点击详情时使用 `id` 调 `GET /api/hq/review/tasks/{id}/detail`。
5. 导出接口与主列表筛选参数一致：`GET /api/hq/review/tasks/export`。
