# 账号状态与服务轨迹前端对接说明

## 状态字段取值

经销商账号和师傅账号统一使用 `status` 表示启用状态。后端保存的标准值为：

| 显示文案 | 请求值 | 返回 `status_code` |
| --- | --- | --- |
| 启用 | `enabled` 或 `启用` | `enabled` |
| 禁用 | `disabled` 或 `禁用` | `disabled` |

`status` 为空或未传时，新增身份默认启用；编辑账号时未传或传空字符串表示不修改原身份状态。

## 账号状态与身份状态

后端现在区分两层状态：

- 账号总状态：`user.status`，禁用后该手机号所有端都不能登录。
- 身份状态：`user_role.status`，只控制某个身份是否可用，例如经销商身份或师傅身份。

经销商管理和师傅管理里的 `status` 都是身份状态，不是账号总状态。

同一个手机号同时有经销商和师傅身份时：

- 在经销商管理禁用，只禁用经销商身份，师傅端仍可登录。
- 在师傅管理禁用，只禁用师傅身份，经销商端仍可登录。
- 登录接口返回的 `roles` 只包含启用身份；前端切换身份时只展示 `roles` 里的身份。
- 如果当前 token 对应的身份被禁用，接口会返回登录失效，重新登录后只能进入仍启用的身份。

上线前需要执行 `migrations/0022_user_role_status.sql`，为 `user_role` 增加身份状态列。没有执行该迁移时，身份状态无法落库。

## 经销商账号接口

### 新增经销商

`POST /api/dealers`

```json
{
  "name": "杭州经销商",
  "mobile": "13800000000",
  "password": "123456",
  "store_ids": [1],
  "status": "enabled"
}
```

### 编辑经销商

`PATCH /api/dealers/{id}`

```json
{
  "name": "杭州经销商",
  "store_ids": [1],
  "status": "disabled"
}
```

### 经销商列表

`GET /api/dealers?status=enabled&page=1&page_size=20`

列表项和详情都会返回：

```json
{
  "status": "已启用",
  "status_code": "enabled",
  "status_text": "已启用"
}
```

前端列表筛选可传 `enabled`、`disabled`、`启用`、`禁用`。

## 师傅账号接口

### 新增师傅

`POST /api/technicians`

```json
{
  "name": "李四",
  "mobile": "13253398607",
  "store_id": 1,
  "service_types": ["cleaning"],
  "status": "enabled"
}
```

### 编辑师傅

`PATCH /api/technicians/{id}`

```json
{
  "name": "李四",
  "mobile": "13253398608",
  "store_id": 1,
  "service_types": ["cleaning"],
  "status": "disabled"
}
```

编辑支持修改登录手机号，但不会覆盖同一用户可能存在的独立后台登录字段 `account`。姓名、手机号、所属门店、服务能力会先统一校验，再以一个事务保存；接口返回校验错误时不会留下部分修改。

### 师傅列表

`GET /api/technicians?status=enabled&page=1&page_size=20`

列表已有状态字段，继续使用 `status_code` 做逻辑判断，`status` / `status_text` 仅用于展示。

## 单独启用禁用

师傅账号可继续使用：

`PATCH /api/technicians/{id}/status`

```json
{
  "status": "禁用"
}
```

后台账号可继续使用：

`PATCH /api/users/{id}/status`

```json
{
  "status": "enabled"
}
```

经销商和师傅的状态变更后，不会禁用手机号账号本身。当前身份的旧 token 会因为身份状态校验而失效，其他启用身份不受影响。

## 服务轨迹调整

`GET /api/tasks/{id}/logs`

服务轨迹只返回任务流转节点，例如创建任务、分派任务、技师开始执行、技师提交检核、关闭任务、总部评分等。

客户评价和经销商评价不再出现在 `logs.items` 中。前端应继续从任务详情接口中的 `customer_review` 和 `dealer_review` 区域展示评价内容。

## 评价和评分字段

任务详情和总部检核详情的评价区域已返回分数：

`GET /api/tasks/{id}`

`GET /api/hq/review/tasks/{id}`

经销商评价：

```json
{
  "dealer_review": {
    "star": 5,
    "score": 5,
    "score_text": "5分",
    "tags": ["非常好"],
    "content": "非常好",
    "created_at": "2026-06-17 17:59:18"
  }
}
```

客户评价：

```json
{
  "customer_review": {
    "star": 5,
    "score": 5,
    "score_text": "5分",
    "tags": ["非常好"],
    "content": "非常好",
    "images": [],
    "created_at": "2026-06-17 17:59:18"
  }
}
```

总部评分：

```json
{
  "hq_score": {
    "total_score": 100,
    "total_score_text": "100分",
    "items": [
      {
        "service_type": "install",
        "score": 100,
        "score_text": "100分",
        "deduction_reason": ""
      }
    ]
  }
}
```

环节记录管理详情的 `service_items[]` 也返回 `score` 和 `score_text`。没有评价或评分时对应对象为 `null`，环节评分 `score_text` 为 `--`。服务轨迹接口不再返回评价节点，因此前端展示分数不要从 `/api/tasks/{id}/logs` 取。
