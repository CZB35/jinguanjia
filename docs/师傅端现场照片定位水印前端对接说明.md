## 适用范围

本文只说明一件事：

- 师傅端上传现场照片时，如何把定位地址传给后端

所有接口默认都挂在 `/api` 下。

## 1. 接口

上传现场照片接口：

```http
POST /tasks/{id}/evidences/images
```

示例：

```http
POST /api/tasks/1001/evidences/images
```

## 2. 请求参数

### 2.1 业务参数

这些字段现在既支持放在 query，也支持放在 `multipart/form-data` 文本字段。

前端推荐直接跟文件一起放在 `form-data`。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `execution_id` | number | 推荐 | 开始执行接口返回的执行记录 ID |
| `service_item_id` | number | 否 | 服务环节子项 ID |
| `service_type` | string | 否 | 服务环节 |
| `location_address` | string | 建议传 | 师傅当前定位地址文本 |

说明：

- `execution_id`、`service_item_id`、`service_type` 三者仍按原规则使用
- `location_address` 是这次新增字段
- `location_address` 直接传前端拿到的可读地址文本，不用传经纬度

### 2.2 表单参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | file | 是 | 现场照片文件 |

## 3. 前端该怎么传

推荐流程：

1. 师傅在小程序端点击上传现场照片
2. 前端先获取当前位置的地址文本
3. 上传图片时，把 `location_address` 作为 `form-data` 文本字段一起传给后端

前端传给后端的是“地址文本”，例如：

```text
杭州市西湖区文三路1号
```

不是经纬度，也不是前端页面展示文案对象。

## 4. 后端处理规则

上传现场照片时，后端会直接把水印写进原图：

1. 如果传了 `location_address`
   - 水印里的地址行优先使用师傅定位地址
2. 如果没传 `location_address`
   - 水印里的地址行回退使用客户地址

也就是说：

- 水印是在上传时定格的
- 后面查看附件、下载附件、批量下载，看到的都是这张已打好水印的原图

## 5. 返回结果

成功后返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 123,
    "file_name": "现场照片.jpg",
    "file_url": "/uploads/evidences/images/xxx.jpg",
    "file_size": 234567,
    "mime_type": "image/jpeg"
  }
}
```

## 6. 联调重点

- 小程序端要确保拿到的是“可读地址文本”后再上传
- `location_address` 推荐直接作为 `form-data` 文本字段传，不必强依赖 query
- 如果任务有多个执行环节，仍建议优先传 `execution_id`
- 如果页面后续查看到的图片地址没变，这是正常的，因为水印已经固化在图片内容里，不会再走二次处理

## 7. 一句话结论

前端现在只需要在上传现场照片时，多传一个：

```text
location_address
```

后端就会把师傅定位地址打进现场照片水印里；不传时自动回退客户地址。
