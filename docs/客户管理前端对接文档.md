# 客户管理前端对接文档

## 适用范围

客户管理接口统一挂在 `/api` 下，需携带 `Authorization: Bearer <token>`。允许角色：`dealer`、`hq_reviewer`、`super_admin`。经销商角色只能查看自己门店或相关任务范围内的客户。

## 客户列表

接口：`GET /api/customers`

查询参数：

| 参数 | 说明 |
| --- | --- |
| `page` | 页码，默认 `1` |
| `page_size` | 每页数量，默认 `20` |
| `mobile` / `customer_mobile` / `customerMobile` / `phone` | 客户手机号模糊搜索 |
| `name` / `customerName` | 客户姓名模糊搜索 |

示例：

```http
GET /api/customers?page=1&page_size=20&mobile=188
```

返回 `data.items`、`data.total`、`data.page`、`data.page_size`。列表字段包含客户基础信息、默认地址、门店、订单数、最近服务日期和最近服务状态。当前排序为客户创建时间倒序，其次按客户 ID 倒序；不是按最新订单排序。

## 新增客户

接口：`POST /api/customers`

```json
{
  "name": "张三",
  "mobile": "18800000000",
  "source": "手工录入",
  "primary_store_id": 1,
  "remark": "重点客户",
  "address": {
    "province": "浙江省",
    "city": "杭州市",
    "district": "拱墅区",
    "detail": "祥符街道门店"
  }
}
```

`name`、`mobile` 必填。手机号不能重复。`source_id`、`customer_source_id` 可替代 `source`。`store_id` 可替代 `primary_store_id`。`address` 也兼容直接传字符串，此时只作为详细地址保存。

## 客户详情与编辑

详情：`GET /api/customers/{id}`

编辑：`PATCH /api/customers/{id}`

编辑字段均可选，支持修改 `name`、`mobile`、`source`、`source_id`、`customer_source_id`、`remark`、`primary_store_id`、`store_id`、`address`。修改地址时 `address.detail` 不能为空；如果已有默认地址则更新默认地址，否则新增默认地址。

## 手机号查客户

接口：`GET /api/customers/search-by-mobile?mobile=188`

用于下单时快速匹配历史客户。返回数组，结构与列表项一致，并包含 `service_history`。

## 服务历史

接口：`GET /api/customers/{id}/service-history`

返回该客户历史任务，按预约时间倒序。每条包含 `task_id`、`task_no`、`service_type`、`task_status`、`service_items`、`technician_name`、`service_date`、`appointment_time`、`store_name`。

## 删除客户

单条删除：`DELETE /api/customers/{id}`

批量删除：`POST /api/customers/batch-delete`

```json
{
  "customer_ids": [12, 13]
}
```

批量接口兼容 `ids`、`customerIds`，数组元素兼容数字和数字字符串。删除采用软删除：客户会从客户列表、手机号搜索和详情接口中隐藏，但历史任务、地址和评价数据不会级联删除。经销商只能删除所属门店范围内的客户。

## 批量导入

模板：`GET /api/users/import-template?import_type=customer`

导入：`POST /api/customers/import`

请求类型：`multipart/form-data`，文件字段建议用 `file`。支持 `csv`、`xls`、`xlsx`。模板中文字段为：`客户姓名`、`客户手机号`、`客户来源`。导入成功返回统计；失败会返回错误文件，前端按 `blob` 下载并提示用户查看原因。
