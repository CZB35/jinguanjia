# 任务列表筛选与列表接口前端对接文档

本文只说明后台“任务管理 -> 任务列表”的列表接口和本次核验状态筛选调整。

## 接口地址

```http
GET /api/tasks
```

分页参数：

| 参数 | 说明 |
| --- | --- |
| `page` | 页码，默认 `1` |
| `page_size` | 每页条数，默认 `20` |

## 筛选参数

| 参数 | 说明 |
| --- | --- |
| `task_no` | 任务编号，模糊匹配 |
| `service_type` | 服务环节 |
| `task_type` | 任务类型，支持 `three_special` / `four_special` |
| `task_status` | 任务状态 |
| `score_status` | 核验状态 |
| `store_id` | 所属门店 ID |
| `technician_id` | 服务师傅 ID |
| `mobile` | 客户手机号，模糊匹配 |
| `customer_name` | 客户姓名，模糊匹配 |
| `appointment_start` | 预约开始时间，格式 `YYYY-MM-DD HH:mm:ss` |
| `appointment_end` | 预约结束时间，格式 `YYYY-MM-DD HH:mm:ss` |

兼容别名：`score_status` 可传 `scoreStatus`、`checkStatus`、`verificationStatus`、`hqReviewStatus`。

## 核验状态

页面下拉只展示两个选项：

| 展示文案 | 推荐请求值 |
| --- | --- |
| 待核验 | `pending` |
| 已核验 | `scored` |

后端也兼容中文请求值：`待核验`、`已核验`。

注意：核验状态对应返回字段是 `score_status` / `score_status_text`。不要使用 `review_status` / `review_status_text`，那是评价状态，会显示“待评价/已评价”。

## 列表列绑定

| 页面列 | 绑定字段 |
| --- | --- |
| 任务ID | `task_no` |
| 任务类型 | `service_items_text` 或 `service_type` |
| 门店 | `store_name` |
| 经销商名称 | `dealer_name` |
| 师傅 | `technician_name` + `technician_mobile` |
| 客户 | `customer_name` + `customer_mobile` |
| 预约时间 | `appointment_time` |
| 任务状态 | `display_status_text` 或 `task_status_text` |
| 核验状态 | `score_status_text` |

## 详情入口

任务列表点击“查看/详情”使用独立详情接口：

```http
GET /api/tasks/{id}/detail
```

不要调用环节记录管理详情接口。环节记录管理详情接口是：

```http
GET /api/hq/review/tasks/{id}/detail
```

## 排序规则

后端按业务最新任务时间排序，多环节任务按任务组和环节顺序排序。前端不要对返回列表再次按 `id` 排序。
