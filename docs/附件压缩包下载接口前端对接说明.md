## 适用范围

本文只说明附件压缩包下载接口：

- `POST /attachments/batch-download`

所有接口默认都挂在 `/api` 下。

## 1. 接口地址

```http
POST /attachments/batch-download
```

## 2. 接口用途

用于把多个附件直接打成一个 `zip` 压缩包下载。

适用场景：

- 任务详情页点击“下载全部附件”
- 环节记录管理点击“批量下载附件”
- 前端勾选多条任务后统一下载附件

## 3. 请求头

```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

## 4. 请求参数

支持两种传法。

### 4.1 按任务下载

```json
{
  "task_ids": [23]
}
```

说明：

- 会把这些任务下的附件统一打包
- 适合“下载当前任务全部附件”

### 4.2 按附件下载

```json
{
  "attachment_ids": [101, 102, 103]
}
```

说明：

- 只会下载这些指定附件
- 适合前端勾选具体文件后下载

### 4.3 两种参数都传

```json
{
  "attachment_ids": [101],
  "task_ids": [23]
}
```

说明：

- 后端会合并去重后统一打包

## 5. 参数规则

- `attachment_ids` 和 `task_ids` 不能同时为空
- 两个字段都是数组
- 元素类型都是数字 ID

如果两个字段都为空，后端会返回：

```text
attachment_ids和task_ids不能同时为空
```

## 6. 返回结果

返回的是压缩包文件流，不是 JSON。

返回类型：

```text
application/zip
```

文件名示例：

```text
task-attachments-20260618-153000.zip
```

或者：

```text
attachments-20260618-153000.zip
```

## 7. 前端推荐接法

### 7.1 下载当前任务全部附件

请求体：

```json
{
  "task_ids": [23]
}
```

### 7.2 下载勾选文件

请求体：

```json
{
  "attachment_ids": [101, 102]
}
```

### 7.3 浏览器处理方式

前端按文件流下载处理，不要按普通 JSON 请求处理。

如果使用 `axios`，建议：

```js
axios.post('/api/attachments/batch-download', payload, {
  responseType: 'blob'
})
```

## 8. 相关接口

如果前端先展示附件列表，再触发下载，可先调用：

- `GET /tasks/{id}/attachments`

这个列表接口会返回：

- 普通附件
- 现场实据

并通过 `source` 区分：

- `attachment`
- `evidence`

## 9. 一句话结论

下载压缩包直接用：

```http
POST /api/attachments/batch-download
```

下载整单附件就传：

```json
{
  "task_ids": [任务ID]
}
```
