# 任务与环节记录多选筛选及全量导出接口前端对接文档

更新时间：2026-08-06

本文说明以下后端变更：

1. 任务列表筛选条件支持多选。
2. 环节记录列表筛选条件支持多选。
3. 新增任务列表“全量导出”独立接口。
4. 新增环节记录列表“全量导出”独立接口。

前端现有字段名不需要修改，列表返回结构也没有变化。

## 1. 公共约定

生产环境接口前缀：

```text
https://service.ryds.cn/api
```

请求需要携带登录令牌：

```http
Authorization: Bearer <access_token>
```

接口错误仍返回统一 JSON：

```json
{
  "code": 9000,
  "message": "系统开小差了，请稍后重试",
  "data": null,
  "request_id": "request-id"
}
```

## 2. 多选参数传递规则

### 2.1 支持多选的字段

任务列表和环节记录列表以下字段均支持多选：

| 字段 | 说明 | 示例值 |
| --- | --- | --- |
| `task_status` | 任务状态 | `pending_execute,executing` |
| `review_status` | 评价状态 | `pending,reviewed` |
| `score_status` | 核验状态 | `pending,scored` |
| `service_type` | 服务环节 | `measure,install` |
| `task_type` | 任务类型 | `three_special,four_special` |

字段名保持不变。单选值仍然兼容，多选推荐把数组使用英文逗号连接后放在原字段中。

单选：

```http
task_status=executing
```

多选：

```http
task_status=pending_execute,executing
```

也兼容把 JSON 数组序列化为一个字符串值：

```text
task_status=["pending_execute","executing"]
```

经过 URL 编码后：

```text
task_status=%5B%22pending_execute%22%2C%22executing%22%5D
```

### 2.2 前端序列化要求

推荐统一使用 `selectedValues.join(',')`：

```ts
const params = {
  ...filters,
  task_status: filters.task_status?.join(',') || undefined,
  review_status: filters.review_status?.join(',') || undefined,
  score_status: filters.score_status?.join(',') || undefined,
  service_type: filters.service_type?.join(',') || undefined,
  task_type: filters.task_type?.join(',') || undefined,
}
```

不要直接发送以下格式：

```text
task_status[]=pending_execute&task_status[]=executing
```

也不要发送同名重复参数：

```text
task_status=pending_execute&task_status=executing
```

未选择任何值时，直接不传该字段。传 `all`、`*`、`全部` 或 `不限` 也会按不筛选处理。

## 3. 任务列表接口（已修改）

```http
GET /api/tasks
```

### 3.1 查询参数

| 参数 | 类型 | 多选 | 说明 |
| --- | --- | --- | --- |
| `task_no` | string | 否 | 任务编号，模糊匹配 |
| `service_type` | string | 是 | 服务环节 |
| `task_type` | string | 是 | 三专/四专 |
| `task_status` | string | 是 | 任务状态 |
| `review_status` | string | 是 | 评价状态 |
| `score_status` | string | 是 | 核验状态 |
| `store_id` | number | 否 | 门店 ID |
| `dealer_user_id` | number | 否 | 经销商账号 ID |
| `technician_id` | number | 否 | 师傅 ID |
| `appointment_start` | string | 否 | 开始时间，`YYYY-MM-DD HH:mm:ss` |
| `appointment_end` | string | 否 | 结束时间，`YYYY-MM-DD HH:mm:ss` |
| `mobile` | string | 否 | 客户手机号，模糊匹配 |
| `customer_name` | string | 否 | 客户姓名，模糊匹配 |
| `page` | number | 否 | 页码，默认 `1` |
| `page_size` | number | 否 | 每页条数，默认 `20` |

兼容别名保持不变：

| 标准字段 | 兼容别名 |
| --- | --- |
| `task_no` | `taskNo` |
| `service_type` | `serviceType` |
| `task_type` | `taskType` |
| `task_status` | `status`、`taskStatus` |
| `review_status` | `reviewStatus` |
| `score_status` | `scoreStatus`、`check_status`、`checkStatus`、`verification_status`、`verificationStatus`、`hq_review_status`、`hqReviewStatus` |
| `store_id` | `storeId` |
| `dealer_user_id` | `dealerUserId` |
| `technician_id` | `technicianId` |
| `appointment_start` | `appointmentStart`、`startDate`、`start_date` |
| `appointment_end` | `appointmentEnd`、`endDate`、`end_date` |
| `mobile` | `customer_mobile`、`customerMobile`、`phone` |
| `customer_name` | `customerName` |

### 3.2 请求示例

查询“待执行或进行中”且服务环节为“量尺或安装”的任务：

```http
GET /api/tasks?page=1&page_size=20&task_status=pending_execute,executing&service_type=measure,install
```

查询“待核验或已核验”的任务：

```http
GET /api/tasks?page=1&page_size=20&score_status=pending,scored
```

### 3.3 返回结构

返回结构没有变化：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "total": 0,
    "summary": {
      "pending_execute": 0,
      "executing": 0,
      "pending_review": 0,
      "completed": 0
    },
    "page": 1,
    "page_size": 20
  }
}
```

`total` 和 `summary` 均为筛选后、分页前的数据；`items` 只包含当前页。

## 5. 任务列表全量导出接口（新增）

```http
GET /api/tasks/export/all
```

用途：任务列表独立“全量导出”按钮。

查询参数与 `GET /api/tasks` 完全一致，包括新增的多选写法。

导出规则：

1. 有筛选条件时，导出符合当前筛选条件的全部记录。
2. 没有筛选条件时，导出当前账号权限范围内的全部任务。
3. `page` 和 `page_size` 不限制导出范围，即使传了分页参数也会导出全部筛选结果。
4. 经销商只导出自己门店范围的数据；师傅只导出自己负责的数据；总部角色按其权限范围导出。
5. 成功响应为二进制 XLSX 文件，不是 JSON。

响应头：

```http
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename="tasks-export.xlsx"
```

按当前筛选条件导出：

```http
GET /api/tasks/export/all?task_status=pending_execute,executing&service_type=measure,install&appointment_start=2026-07-31%2000:00:00&appointment_end=2026-08-06%2023:59:59
```

不带条件，导出权限范围内全部任务：

```http
GET /api/tasks/export/all
```

导出文件包含以下基础列，并根据现场图片数量动态追加“附件图片”列：

| XLSX 列 |
| --- |
| 客户手机号 |
| 客户姓名 |
| 任务类型（服务环节中文） |
| 师傅姓名 |
| 师傅手机号 |
| 师傅评分 |
| 门店 |
| 经销商名称 |
| 经销商评价 |
| 客户评价 |
| 客户地址 |
| 师傅定位地址 |
| 附件图片、附件图片2…… |

兼容说明：原接口 `GET /api/tasks/export` 保留，行为与新全量导出接口一致。新按钮建议使用 `/api/tasks/export/all`，便于和“导出选中项”区分。

2. 没有筛选条件时，导出当前账号权限范围内的全部环节记录。
3. `page` 和 `page_size` 不限制导出范围。
4. 成功响应为二进制 XLSX 文件，不是 JSON。

## 7. “导出选中项”接口保持不变

任务列表导出选中项：

```http
POST /api/tasks/export/selected
Content-Type: application/json

{
  "task_ids": [101, 102]
}
```

环节记录导出选中项：

```http
POST /api/hq/review/tasks/export/selected
Content-Type: application/json

{
  "task_ids": [101, 102],
  "service_item_ids": [1001, 1002]
}
```

按钮对应关系：

| 页面操作 | 请求接口 |
| --- | --- |
| 任务列表：导出选中项 | `POST /api/tasks/export/selected` |
| 任务列表：全量导出 | `GET /api/tasks/export/all` |
| 环节记录：导出选中项 | `POST /api/hq/review/tasks/export/selected` |
| 环节记录：全量导出 | `GET /api/hq/review/tasks/export/all` |

## 8. 前端下载示例

以下示例以 Axios 风格请求实例为例：

```ts
function normalizeListParams(filters: Record<string, any>) {
  const multiFields = [
    'task_status',
    'review_status',
    'score_status',
    'service_type',
    'task_type',
  ]

  const params = { ...filters }
  for (const field of multiFields) {
    if (Array.isArray(params[field])) {
      params[field] = params[field].length ? params[field].join(',') : undefined
    }
  }
  return params
}

async function exportAllTasks(filters: Record<string, any>) {
  const response = await request.get('/tasks/export/all', {
    params: normalizeListParams(filters),
    responseType: 'blob',
  })

  const blob = new Blob([response.data], {
    type: 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet',
  })
  const url = URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.href = url
  link.download = 'tasks-export.xlsx'
  link.click()
  URL.revokeObjectURL(url)
}

async function exportAllReviewRecords(filters: Record<string, any>) {
  const response = await request.get('/hq/review/tasks/export/all', {
    params: normalizeListParams(filters),
    responseType: 'blob',
  })

  const blob = new Blob([response.data], {
    type: 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet',
  })
  const url = URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.href = url
  link.download = 'review-tasks-export.xlsx'
  link.click()
  URL.revokeObjectURL(url)
}
```

前端点击导出后应显示加载状态并禁止重复点击。导出包含图片时，文件生成时间会比普通列表请求更长。

## 9. 联调验收项

1. 任务状态选择两项后，请求仍使用 `task_status`，值为英文逗号连接的字符串。
2. 核验状态选择两项后，请求仍使用 `score_status`。
3. 清空多选后不传对应字段，列表恢复全部结果。
4. 列表分页正常，`total` 为筛选后总数。
5. 全量导出携带与列表相同的筛选参数。
6. 全量导出不受当前页和每页条数限制。
7. 不带筛选条件点击全量导出时，导出权限范围内全部数据。
8. 全量导出和导出选中项是两个独立按钮、两个独立接口。
9. 下载请求必须设置 `responseType: 'blob'`。
10. 下载后的文件扩展名必须为 `.xlsx`。
