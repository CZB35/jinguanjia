# 客户、师傅、经销商删除与师傅默认密码前端对接文档

## 1. 通用说明

- 接口统一挂载在 `/api` 下。
- 请求头需携带 `Authorization: Bearer <token>`。
- 单条删除使用 `DELETE`，批量删除使用 `POST`。
- 删除均为软删除，不会级联删除历史任务、服务记录、评价或附件。
- 删除成功后，前端刷新当前管理列表即可，不应同步删除任务列表中的历史数据。

## 2. 新增师傅默认密码

接口：`POST /api/technicians`

`password` 已改为非必填字段。不传、传 `null` 或传空字符串时，后端统一使用默认密码 `123456`。

推荐请求：

```json
{
  "name": "张师傅",
  "mobile": "13800009999",
  "store_id": 1,
  "service_types": ["install", "cleaning"],
  "status": "enabled"
}
```

如需指定其他初始密码，可传：

```json
{
  "name": "张师傅",
  "mobile": "13800009999",
  "password": "abc123456",
  "store_id": 1,
  "service_types": ["install"]
}
```

密码规则：

- 不传或传空值：使用 `123456`。
- 主动传入密码：去除首尾空格后长度不能少于 6 位。
- 前端“初始密码”字段不需要必填校验，可提示“默认初始密码123456”。

## 3. 客户删除

允许角色：`dealer`、`hq_reviewer`、`super_admin`。

经销商只能删除所属门店或所属门店历史任务范围内的客户。

### 3.1 单条删除

```http
DELETE /api/customers/{id}
```

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "ok": true
  },
  "request_id": "uuid"
}
```

### 3.2 批量删除

```http
POST /api/customers/batch-delete
Content-Type: application/json
```

标准请求：

```json
{
  "customer_ids": [12, 13, 14]
}
```

兼容字段：`ids`、`customerIds`。数组元素支持数字或数字字符串。

客户删除后的行为：

- 客户不再出现在客户列表和手机号搜索结果中。
- 客户详情接口返回客户不存在或已删除。
- 客户地址、历史任务和评价数据继续保留。
- 使用该手机号重新新增客户时会提示手机号已存在；新增任务时会明确提示该客户已删除，需要管理员处理。

## 4. 师傅删除

允许角色：`dealer`、`hq_reviewer`、`super_admin`。

经销商只能删除所属门店下的师傅。

### 4.1 单条删除

```http
DELETE /api/technicians/{id}
```

### 4.2 批量删除

```http
POST /api/technicians/batch-delete
Content-Type: application/json
```

标准请求：

```json
{
  "technician_ids": [21, 22]
}
```

兼容字段：`ids`、`user_ids`、`technicianIds`。数组元素支持数字或数字字符串。

师傅删除后的行为：

- 师傅不再出现在师傅列表和可分配师傅列表中。
- 师傅现有登录凭证立即失效。
- 通过旧师傅 ID 直接发起任务分派也会被拒绝。
- 历史任务中的师傅姓名、执行记录、评分和现场资料继续保留。
- 已分派但未完成的任务不会自动改派，需要管理人员重新分派。

## 5. 经销商删除

允许角色：`hq_reviewer`、`super_admin`。

### 5.1 单条删除

```http
DELETE /api/dealers/{id}
```

### 5.2 批量删除

```http
POST /api/dealers/batch-delete
Content-Type: application/json
```

标准请求：

```json
{
  "dealer_ids": [31, 32]
}
```

兼容字段：`ids`、`user_ids`、`dealerIds`。数组元素支持数字或数字字符串。

经销商删除后的行为：

- 经销商不再出现在经销商列表中。
- 经销商现有登录凭证立即失效。
- 经销商创建的历史任务仍按原门店保留，其他有权限的账号仍可查看和维护。

## 6. 批量删除响应

三类批量删除接口统一返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "ok": true,
    "deleted_count": 2
  },
  "request_id": "uuid"
}
```

批量处理规则：

- ID 列表不能为空。
- ID 必须为正整数。
- 重复 ID 会自动去重。
- 后端会先校验全部 ID、数据类型和权限，再执行删除。
- 当前登录账号不能删除自己。

## 7. 常见错误

| HTTP 状态码 | 业务码 | 场景 |
| --- | --- | --- |
| `400` | `1001` | ID 列表为空、包含非法 ID，或尝试删除当前登录账号 |
| `401` | `1006` | 未登录、登录已失效 |
| `403` | `1007` | 无删除权限，或经销商操作了其他门店数据 |
| `404` | `2001` | 数据不存在或已删除 |
| `409` | `2002` | 数据状态冲突 |

错误响应示例：

```json
{
  "code": 1007,
  "message": "您只能删除所属门店范围内的客户",
  "data": null,
  "request_id": "uuid"
}
```

## 8. 前端列表交互建议

1. 单条删除前弹出二次确认框。
2. 批量删除按钮仅在已勾选数据时启用。
3. 删除成功后清空勾选状态并重新请求当前页列表。
4. 当前页删除后为空时，页码大于 1 的情况下回退一页再请求。
5. 删除师傅时提示“未完成任务不会自动改派”。
6. 不要因为删除客户、师傅或经销商而清理任务列表缓存中的历史任务。

## 9. 后端发布要求

客户软删除依赖数据库字段 `customer.deleted_at`。部署新版本前需按顺序手动执行：

```text
migrations/0024_customer_soft_delete.sql
```

师傅和经销商复用现有 `user.deleted_at`，不需要额外数据库字段。
