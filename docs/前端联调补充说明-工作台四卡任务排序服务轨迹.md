## 适用范围

本说明只覆盖最近这 3 个前端联调点：

- 工作台顶部四卡
- 任务列表默认排序
- 服务轨迹/任务日志文案

所有接口默认都挂在 `/api` 下。

## 1. 任务列表默认排序

接口：

```http
GET /tasks
```

当前后端已调整为：

- 最新订单默认在前
- 主要按 `appointment_time` 倒序
- 同时间再按 `task_no`、`id` 倒序

前端无需额外排序，直接使用接口返回顺序即可。

## 2. 工作台顶部四卡

接口：

- 经销商工作台：

```http
GET /dealer/dashboard
```

- 总部工作台：

```http
GET /hq/dashboard
```

- 师傅工作台：

```http
GET /technician/dashboard
```

### 新增字段

返回里新增：

```json
service_overview_cards: []
```

每项结构：

```json
{
  "service_type": "measure",
  "title": "量尺任务",
  "total_count": 102,
  "completion_rate": 95.0
}
```

固定返回 4 个服务环节：

- `measure` -> `量尺任务`
- `install` -> `安装任务`
- `ironing` -> `熨烫任务`
- `cleaning` -> `除尘除螨任务`

### 前端接法

工作台顶部四卡不要再用旧的：

- `pending_task_count`
- `pending_review_task_count`
- `month_completed_count`
- `total_tasks`

而是改成直接读：

```json
service_overview_cards
```

推荐映射：

- 卡片标题：`title`
- 大数字：`total_count`
- 完成率：`completion_rate`

### 示例

```ts
const cards = dashboard.service_overview_cards
```

前端按返回顺序渲染 4 张卡即可。

## 3. 服务轨迹 / 任务日志文案

接口：

```http
GET /tasks/{id}/logs
```

### 当前变化

后端 `action` 已改成更适合直接展示的中文文案，不需要前端再做英文动作码翻译。

### 现在会返回的典型节点

- `创建任务`
- `分派任务`
- `任务重派`
- `技师开始执行任务`
- `技师提交检核`
- `客户评价：非常好`
- `总部评分完成`
- `关闭任务`

### 重点说明

以前可能看到：

- `submit_task`
- `hq_score`
- `dealer_review`

现在前端应直接展示后端返回的 `action` 文本，不要再按旧英文值做映射。

## 4. 前端最小改动清单

### 任务列表

- 直接使用接口返回顺序
- 不要再在前端把旧订单排到前面

### 工作台顶部四卡

- 改读 `service_overview_cards`
- 每张卡展示：`title` / `total_count` / `completion_rate`

### 服务轨迹 / 任务日志

- 直接展示 `action`
- 不要再把 `submit_task`、`hq_score` 等英文动作码写死在前端映射里
