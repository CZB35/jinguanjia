# 前端联调修复清单

本清单汇总本轮已完成的后端修复，前端联调时请按这里的结论接入。

## 基础访问

1. HTTPS 基地址使用 `https://goldenbutler.friendchenkeji.cn/api`
2. 不要再带 `:3001`
3. 健康检查：`GET /health`

## 已修复项

1. `GET /me/profile` 已补门店字段
字段：`store_id`、`store_ids`、`primary_store_id`、`primary_store_name`、`store_names`

2. 经销商主链路门店来源已统一
建议前端统一使用 `me/profile.store_id` 作为当前门店来源

3. 门店接口已按页面字段扩展
新增/返回支持：`name/store_name`、`code`、`remark`、`province`、`city`、`district`、`region_text`

4. 经销商门店/师傅范围已收口
经销商只能看到自己门店和自己门店下师傅；新增师傅会自动归属到经销商所属门店

5. 客户手机号搜索已支持模糊匹配
接口：`GET /customers/search-by-mobile`

6. 师傅端任务状态已修复
当任务进入 `pending_hq_score` 时，师傅视角显示“已完成”，不再显示“已评价”

7. 上传返回路径已改
所有上传相关 `file_url` 现在返回可直接访问的 `/uploads/...` 路径，前端不要再自行拼接

8. 环节记录管理支持三专/四专筛选
接口：`GET /hq/review/tasks`、`GET /hq/review/tasks/export`
参数：`task_type=三专/四专` 或 `three_special/four_special`

9. 经销商列表统计已修复一部分口径
`technician_count` 现在只统计真正的师傅账号

10. 后台角色管理/权限树已补齐
支持：角色 CRUD、嵌套权限树、角色权限码回写

11. 后台管理员页角色码已兼容
支持前端传：`admin`、`inspection_admin`、`dealer_manager`、`readonly_admin`

12. 经销商导入模板已补
下载接口：`GET /users/import-template?role_code=dealer`
导入接口：`POST /users/import`
支持文件：`csv/xls/xlsx`

13. 分配任务页可用师傅筛选已补齐
`GET /technicians/available` 已按师傅 `service_types` 精确过滤；`GET /technicians/available/grouped` 支持按多个服务类型分组返回

14. 分配任务接口已支持服务环节维度
`POST /tasks/{id}/assign` 支持 `service_type`、`service_item_id` 和 `assignments`，兼容旧的 `technician_id` 单师傅分配请求

15. 师傅端任务已按服务环节拆分
同一任务多个服务环节分给同一师傅时，`GET /tasks` 会按 `service_item_id` 返回多条任务卡片；开始执行、上传实据、提交任务支持 `service_item_id/execution_id`

## 分配任务页

适用页面：

1. 经销商端分配任务页
2. 后台分配任务页

已补接口：

1. `GET /technicians/available`
2. `GET /technicians/available/grouped`
3. `POST /tasks/{id}/assign`

说明：

1. `GET /technicians/available?store_id=3&service_type=install` 只返回 `service_types` 包含 `install` 的师傅
2. `GET /technicians/available/grouped?store_id=3&service_types=install,ironing` 按服务类型分组返回可分配师傅
3. `POST /tasks/{id}/assign` 可传 `service_type` 或 `service_item_id` 指定服务环节
4. 多环节批量分配可传 `assignments: [{ "service_type": "install", "technician_id": 28 }]`

## 角色管理

适用页面：

1. 后台角色列表
2. 后台新增角色
3. 后台编辑角色
4. 后台角色详情

已补接口：

1. `GET /system/roles`
2. `GET /system/roles/{id}`
3. `POST /system/roles`
4. `PATCH /system/roles/{id}`
5. `DELETE /system/roles/{id}`
6. `GET /system/roles/{id}/permissions`
7. `PATCH /system/roles/{id}/permissions`

角色返回关键字段：

1. `id`
2. `role_code`
3. `role_name`
4. `name`
5. `remark`
6. `status`
7. `created_at`
8. `updated_at`
9. `permission_ids`
10. `permission_keys`

说明：

1. 前端角色页里的“角色名称”可直接用 `role_name` 或 `name`
2. 前端角色页里的“角色ID”可直接用 `role_code`
3. 权限勾选建议直接用 `permission_keys`
4. `role_code` 不传时，后端自动生成 `ROLE-001` 这类编码

## 权限管理

适用页面：

1. 后台权限树展示
2. 角色授权弹窗/抽屉

已补接口：

1. `GET /system/permission-tree`

权限树返回结构：

1. `id`
2. `key`
3. `title`
4. `permission_code`
5. `permission_name`
6. `permission_type`
7. `parent_id`
8. `sort_no`
9. `children`

说明：

1. 后端已按后台页面那套权限码补种权限树
2. 当前根节点为：`workspace`、`tasks`、`users`、`settings`、`master-data`
3. `GET /system/permission-tree` 现在优先返回后台角色页这套树，不再混旧权限结构
