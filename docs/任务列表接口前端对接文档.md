## 适用范围

本文只说明任务列表接口：

- `GET /tasks`
- `DELETE /tasks/{id}`
- `POST /tasks/batch-delete`

所有接口默认都挂在 `/api` 下。

## 1. 接口地址

```http
GET /tasks
```

示例：

```text
https://service.ryds.cn/api/tasks?page=1&page_size=20
```

## 2. 分页参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `page` | number | 否 | 页码，默认 `1` |
| `page_size` | number | 否 | 每页条数，默认 `20` |

## 3. 筛选参数

### 3.1 标准参数

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `task_no` | string | 任务编号 |
| `service_type` | string | 服务环节 |
| `task_type` | string | 任务类型 |
| `task_status` | string | 任务状态 |
| `review_status` | string | 评价状态 |
| `score_status` | string | 核验状态 |
| `store_id` | number | 所属门店 ID |
| `dealer_user_id` | number | 经销商账号 ID |
| `technician_id` | number | 师傅 ID |
| `appointment_start` | string | 预约开始时间，格式 `YYYY-MM-DD HH:mm:ss` |
| `appointment_end` | string | 预约结束时间，格式 `YYYY-MM-DD HH:mm:ss` |
| `mobile` | string | 客户手机号 |
| `customer_name` | string | 客户姓名 |

### 3.2 兼容别名

后端当前已兼容以下前端常见写法：

| 标准参数 | 兼容别名 |
| --- | --- |
| `task_no` | `taskNo` |
| `service_type` | `serviceType` |
| `task_type` | `taskType` |
| `task_status` | `status`、`taskStatus` |
| `review_status` | `reviewStatus` |
| `score_status` | `scoreStatus`、`checkStatus`、`verificationStatus`、`hqReviewStatus` |
| `store_id` | `storeId` |
| `dealer_user_id` | `dealerUserId` |
| `technician_id` | `technicianId` |
| `appointment_start` | `appointmentStart`、`startDate`、`start_date` |
| `appointment_end` | `appointmentEnd`、`endDate`、`end_date` |
| `mobile` | `customer_mobile`、`customerMobile`、`phone` |
| `customer_name` | `customerName` |

前端建议：

- 新页面尽量统一只用标准参数名
- 老页面如果还没改完，后端当前仍兼容别名

## 4. `task_type` 说明

支持传：

- `three_special`
- `four_special`
- `三专`
- `四专`
- `3`
- `4`

说明：

- `three_special` 表示三专
- `four_special` 表示四专
- 当前任务列表按同组真实服务环节数判定三专/四专
- 不是单纯按单条任务字面值判定

## 7. 核验状态筛选

页面下拉只展示两个选项：

| 展示文案 | 请求值 |
| --- | --- |
| 待核验 | `pending` 或 `待核验` |
| 已核验 | `scored` 或 `已核验` |

任务列表的“核验状态”列必须绑定 `score_status_text`，不要绑定 `review_status_text`。`review_status_text` 是经销商/客户评价状态，所以会显示“待评价/已评价”。

## 8. 评价分数字段

任务详情接口 `GET /api/tasks/{id}` 的评价区域会返回分数：

```json
{
  "dealer_review": {
    "star": 5,
    "score": 5,
    "score_text": "5分",
    "content": "非常好"
  },
  "customer_review": {
    "star": 5,
    "score": 5,
    "score_text": "5分",
    "content": "非常好"
  }
}
```

前端展示星级用 `star`，展示文字分数用 `score_text`。

## 9. 排序规则

当前任务列表不是简单按 `id` 倒序。

当前默认规则：

- 优先按业务最新订单时间排序
- 多环节同组任务会按组排序 + 环节顺序排序

所以前端不要再自行对返回结果二次重排。

## 10. 前端联调建议

1. 分页统一传：

```text
page=1&page_size=20
```

2. 筛选尽量只用标准参数名

3. 列表页如果是多环节任务卡片场景，建议保留：

- `id`
- `service_item_id`
- `service_type`

后续查看详情、上传实据、提交任务时会继续用到

## 11. 任务删除

允许角色：`dealer`、`hq_reviewer`、`super_admin`。经销商只能删除所属门店的任务，师傅账号不能删除任务。

### 11.1 单条删除

```http
DELETE /api/tasks/{id}
```

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "ok": true
  },
  "request_id": "uuid"
}
```

### 11.2 批量删除

```http
POST /api/tasks/batch-delete
Content-Type: application/json
```

标准请求：

```json
{
  "task_ids": [101, 102, 103]
}
```

兼容字段：`ids`、`taskIds`。数组元素支持数字或数字字符串，重复 ID 会自动去重。

批量成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "ok": true,
    "deleted_count": 3
  },
  "request_id": "uuid"
}
```

删除规则：

- 删除采用软删除，任务会从任务列表、导出、总部审核、看板、报表、客户服务历史和师傅任务中隐藏。
- 任务详情、附件、实据、评价、评分和任务动作接口会把已删除任务视为不存在。
- 执行记录、服务环节、评价、评分、附件和现场实据仍保留在数据库中，不做物理级联删除。
- 删除进行中或已分派任务不会自动改派，前端应在删除前明确二次确认。
- 批量接口会先校验全部任务和权限，再执行删除。
