## 适用范围

本文是独立对接文档，只覆盖两部分：

- 批量导入经销商 / 客户 / 门店
- 任务详情 / 环节记录详情中的经销商评价、客户评价模块展示

所有接口默认都挂在 `/api` 下。

## 1. 批量导入

### 1.1 经销商批量导入

接口：

```http
POST /dealers/import
Content-Type: multipart/form-data
```

上传说明：

- 上传文件即可，建议字段名使用 `file`
- 支持 `csv` / `xls` / `xlsx`

模板字段：

- `姓名`
- `手机号`
- `密码`
- `所属门店`
- `状态`

说明：

- 经销商默认按经销商角色导入，不需要前端再传角色编码
- 经销商必须且只能绑定一个门店
- `所属门店` 填门店名称或门店编码，不要填数据库 ID
- `状态` 支持：`启用` / `禁用` / `enabled` / `disabled` / `active` / `inactive`
- `状态` 可留空，留空默认按 `启用` 导入

### 1.2 客户批量导入

接口：

```http
POST /customers/import
Content-Type: multipart/form-data
```

模板字段：

- `客户姓名`
- `客户手机号`
- `客户来源`
- `所属门店`
- `省`
- `市`
- `区`
- `详细地址`
- `备注`

说明：

- 客户手机号不能重复
- `所属门店` 如填写，后端会按门店名称或门店编码匹配门店
- `客户来源` 建议传中文名称，例如 `手工录入`
- `客户来源` 也兼容来源编码或来源名称
- 不传 `客户来源` 时，默认按 `手工录入` 处理
- `详细地址` 为空时只创建客户，不创建默认地址记录

### 1.3 门店批量导入

接口：

```http
POST /stores/import
Content-Type: multipart/form-data
```

模板字段：

- `门店名称`
- `门店编码`
- `省`
- `市`
- `区`
- `详细地址`
- `联系人`
- `联系电话`
- `营业时间`
- `备注`
- `状态`

说明：

- `门店名称` 不能为空，且不能重复
- `门店编码` 可留空；如果填写，不能重复
- `状态` 支持：`启用` / `禁用` / `enabled` / `disabled` / `active` / `inactive`
- `状态` 可留空，留空默认按 `启用` 导入

## 2. 导入模板下载

统一模板下载接口：

```http
GET /users/import-template
```

### 2.1 后台账号模板

```http
GET /users/import-template
```

返回文件名：

```text
users-import-template.xlsx
```

说明：

- 后台账号模板中的 `所属门店` 填门店名称或门店编码
- 模板文件已改成 `xlsx`，不再出现 `sep=` 行

### 2.2 经销商模板

```http
GET /users/import-template?role_code=dealer
```

返回文件名：

```text
dealers-import-template.xlsx
```

### 2.3 客户模板

```http
GET /users/import-template?import_type=customer
```

返回文件名：

```text
customers-import-template.xlsx
```

### 2.4 门店模板

```http
GET /users/import-template?import_type=store
```

返回文件名：

```text
stores-import-template.xlsx
```

## 3. 导入统一返回结构

所有导入接口统一返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "success_count": 10,
    "failed_count": 2,
    "errors": [
      "第3行手机号已存在: 13800001111",
      "第5行所属门店不存在: 西湖一店"
    ],
    "error_file_name": "customers-import-errors.xlsx",
    "error_file_base64": "UEsDB..."
  }
}
```

前端建议：

- 成功后提示：成功条数 / 失败条数
- 若 `errors` 不为空，支持展开查看失败原因
- 若 `error_file_base64` 不为空，前端直接解码并自动下载 `error_file_name`
- 失败明细文件是 `xlsx`，其中包含原始导入数据和失败原因

前端处理示例：

```js
const binary = atob(data.error_file_base64)
const bytes = Uint8Array.from(binary, (char) => char.charCodeAt(0))
const blob = new Blob([bytes], { type: 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet' })
```

## 4. 任务详情评价模块

接口：

```http
GET /tasks/{id}
```

当前新增两个模块字段：

- `dealer_review`
- `customer_review`

### 4.1 经销商评价字段

结构：

```json
{
  "star": 5,
  "tags": ["准时", "专业"],
  "content": "服务很好，处理很及时",
  "created_at": "2026-06-15 10:20:30"
}
```

前端重点展示：

- 评分：`dealer_review.star`
- 标签：`dealer_review.tags`
- 评价内容：`dealer_review.content`
- 评价时间：`dealer_review.created_at`

### 4.2 客户评价字段

结构：

```json
{
  "star": 5,
  "tags": ["满意", "干净整洁"],
  "content": "师傅很细心，整体很满意",
  "images": [
    {
      "id": 1,
      "file_url": "/uploads/customer-reviews/xxx.jpg"
    }
  ],
  "created_at": "2026-06-15 10:30:12"
}
```

前端重点展示：

- 评分：`customer_review.star`
- 标签：`customer_review.tags`
- 评价内容：`customer_review.content`
- 图片：`customer_review.images`
- 评价时间：`customer_review.created_at`

### 4.3 空数据处理

如果字段为 `null`，前端建议直接显示：

```text
暂无评价
```

## 5. 环节记录详情评价模块

接口：

```http
GET /hq/review/tasks/{id}
```

当前同样新增：

- `dealer_review`
- `customer_review`

字段结构与任务详情保持一致。

也就是说，环节记录详情页可以直接复用任务详情页的评价模块组件。

## 6. 前端页面建议

### 6.1 任务管理 -> 任务详情

建议新增两个模块：

- `经销商评价`
- `客户评价`

模块内展示：

- 星级
- 标签
- 评价内容
- 评价时间
- 客户评价图片（如有）

### 6.2 环节记录管理 -> 查看详情

建议同样新增两个模块：

- `经销商评价`
- `客户评价`

展示字段与任务详情一致。
