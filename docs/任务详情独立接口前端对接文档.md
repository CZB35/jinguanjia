# 任务详情独立接口前端对接文档

本文只说明两个后台抽屉详情接口。任务列表和环节记录管理不要混用同一个详情接口。

## 1. 任务列表详情

用于后台“任务管理 -> 任务列表 -> 查看/详情”抽屉。

```http
GET /api/tasks/{id}/detail
```

兼容旧接口：

```http
GET /api/tasks/{id}
```

重点字段：

```json
{
  "task_status_text": "待评价",
  "score_status": "pending",
  "score_status_text": "待核验",
  "dealer_review": {
    "star": 5,
    "score": 5,
    "score_text": "5分",
    "content": "非常好"
  },
  "customer_review": {
    "star": 5,
    "score": 5,
    "score_text": "5分",
    "content": "非常好"
  },
  "hq_score": {
    "total_score": 100,
    "total_score_text": "100分",
    "items": [
      {
        "service_type": "install",
        "score": 100,
        "score_text": "100分",
        "deduction_reason": ""
      }
    ]
  }
}
```

说明：

- 经销商评价展示 `dealer_review.star` 或 `dealer_review.score_text`。
- 客户评价展示 `customer_review.star` 或 `customer_review.score_text`。
- 总部核验评分展示 `hq_score.total_score_text`，环节评分展示 `hq_score.items[].score_text`。
- 没有评价时 `dealer_review` 或 `customer_review` 为 `null`。

## 2. 环节记录管理详情

用于后台“任务管理 -> 环节记录管理 -> 查看/详情”抽屉。

```http
GET /api/hq/review/tasks/{id}/detail
```

兼容旧接口：

```http
GET /api/hq/review/tasks/{id}
```

重点字段：

```json
{
  "task_status": "completed",
  "score_status": "scored",
  "dealer_review": {
    "star": 4,
    "score": 4,
    "score_text": "4分",
    "content": "还好吧"
  },
  "customer_review": null,
  "service_items": [
    {
      "service_type": "install",
      "score": 100,
      "score_text": "100分",
      "deduction_reason": ""
    }
  ]
}
```

说明：

- 环节记录管理里的“师傅评分/总部评分”展示 `service_items[].score_text`。
- 经销商评价和客户评价仍从 `dealer_review`、`customer_review` 取。
- 没有环节评分时 `service_items[].score` 为 `null`，`score_text` 为 `--`。

## 3. 核验状态

页面只展示两个状态：

| 展示文案 | 接口编码 |
| --- | --- |
| 待核验 | `pending` |
| 已核验 | `scored` |

任务列表的“核验状态”列绑定 `score_status_text`，不要绑定 `review_status_text`。`review_status_text` 是评价状态，会显示“待评价/已评价”。
