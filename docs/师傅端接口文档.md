# 师傅端接口文档

## 1. 基本信息

- 端：师傅端
- 接口前缀：`/api`
- 当前状态：`已实现` + `已完成冒烟测试`

## 2. 通用返回结构

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | number | 业务码，`0` 表示成功 |
| `message` | string | 返回消息 |
| `data` | object | 业务数据 |
| `request_id` | string | 请求追踪 ID |

## 3. 页面与接口

### 3.1 登录页

- `POST /auth/login/password`：密码登录
- `POST /auth/code/send`：发送验证码
- `POST /auth/login/code`：验证码登录

关键字段与经销商端一致。

补充说明：

1. `role_code` 可不传
2. 后端返回 `roles`、`current_role`、`switchable`
3. 单角色师傅账号通常返回：`roles=["technician"]`、`switchable=false`
4. 请求头需要带：`Authorization: Bearer <access_token>`
5. 如果当前端是师傅独立登录页，也可以固定传 `role_code=technician`

### 3.3 任务列表页

#### 3.3.1 我的任务列表

- 接口：`GET /tasks`
- 状态：`已实现` `已测试`

师傅端常用字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | number | 任务主单 ID |
| `service_item_id` | number | 服务环节子项 ID；同一任务多个环节会返回多条任务卡片，前端列表 key 建议用 `${id}-${service_item_id}` |
| `task_no` | string | 任务单号 |
| `service_type` | string | 当前任务卡片对应的服务环节 |
| `service_status` | string | 当前服务环节状态 |
| `service_items_text` | string | 服务项目中文组合 |
| `task_status_text` | string | 任务状态中文 |
| `display_status` | string | 页面展示状态编码 |
| `display_status_text` | string | 页面展示状态中文 |
| `customer_name` | string | 客户姓名 |
| `customer_mobile` | string | 客户手机号 |
| `address` | string | 服务地址 |
| `technician_name` | string | 当前师傅 |
| `progress_percent` | number | 进度百分比 |
| `is_overdue` | boolean | 是否逾期 |
| `task_tags` | string[] | 标签列表 |

多服务环节说明：

1. 师傅端任务列表按 `task_service_item` 拆分。
2. 如果同一个任务的 `install` 和 `ironing` 都分给李师傅，李师傅会看到两条任务卡片。
3. 每条任务卡片的 `service_item_id` 不同，`service_type` 分别为 `install`、`ironing`。
4. 后续开始执行、上传实据、提交任务建议都带上对应的 `service_item_id` 或 `execution_id`。

#### 3.6.2 上传图片实据

- 接口：`POST /tasks/{id}/evidences/images`
- 状态：`已实现` `已测试`

可选参数：

这些字段现在既支持放在 query，也支持直接放在 `multipart/form-data` 文本字段里。

前端推荐：

- 文件走 `file`
- 其他字段直接跟文件一起放在 `form-data`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `execution_id` | number | 执行记录 ID，推荐传开始执行接口返回的值 |
| `service_item_id` | number | 服务环节子项 ID |
| `service_type` | string | 服务环节 |
| `location_address` | string | 师傅上传时定位地址文本，建议传 |

示例：

```http
POST /api/tasks/1001/evidences/images
```

表单字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `file` | file | 图片文件 |
| `execution_id` | text | 执行记录 ID，推荐传 |
| `service_item_id` | text | 服务环节子项 ID |
| `service_type` | text | 服务环节 |
| `location_address` | text | 师傅上传时定位地址文本 |

返回字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | number | 实据 ID |
| `file_name` | string | 文件名 |
| `file_url` | string | 可直接访问的文件路径，格式如 `/uploads/evidences/images/...` |
| `file_size` | number | 文件大小 |
| `mime_type` | string | 文件类型 |

上传规则补充：

1. 现场图片水印在上传时直接写入原图。
2. 如果传了 `location_address`，水印里的地址行优先使用师傅定位地址。
3. 如果没有传 `location_address`，水印里的地址行回退使用客户地址。
4. 后续查看附件、下载附件、批量下载时，看到的都是这张已固化水印的原图。
5. 小程序端建议先获取定位地址，再把 `location_address` 传给后端。
6. 现场图片大小不能超过 `10MB`。

#### 3.6.3 上传视频实据

- 接口：`POST /tasks/{id}/evidences/videos`
- 状态：`已实现` `已实现未单独冒烟`

上传规则：

1. 所有服务环节均支持上传视频，包括 `measure`、`install`、`ironing`、`cleaning`
2. 视频上传时也会直接固化水印
3. 视频水印里的地址行规则与现场图片一致：
   - 优先使用 `location_address`
   - 没传时回退客户地址
4. 现场视频大小不能超过 `50MB`

建议参数：

这些字段现在既支持放在 query，也支持直接放在 `multipart/form-data` 文本字段里。

前端推荐直接走 `form-data`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `execution_id` | number | 执行记录 ID，推荐传 |
| `service_item_id` | number | 服务环节子项 ID |
| `service_type` | string | 服务环节 |
| `location_address` | string | 师傅当前定位地址文本，建议传 |

#### 3.6.6 提交任务

- 接口：`POST /tasks/{id}/submit`
- 状态：`已实现` `已测试`

请求字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `execution_id` | number | 执行记录 ID |
| `service_item_id` | number | 服务环节子项 ID，推荐传 |
| `service_type` | string | 服务环节，未传 `service_item_id` 时可传 |
| `submit_remark` | string | 提交备注 |

提交规则：

1. 提交会更新当前服务环节状态，不会把同一任务的其他服务环节一起提交。
2. 同一任务全部服务环节提交后，任务主状态才会进入 `pending_dealer_review`。
3. 如果只提交了其中一个服务环节，任务主状态保持 `executing`。
4. 任务进入 `pending_dealer_review` 后，后端会给客户手机号发送评价短信；手机号必须是完整中国大陆手机号，规则为 `^1[3-9]\d{9}$`，例如 `18838962531` 会通过，只有 `188` 或空值不会发送。
