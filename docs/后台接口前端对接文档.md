# 后台接口前端对接文档

## 1. 说明

这份文档给前端直接对接使用，聚焦本轮已修复和已确认的后台接口问题。

优先规则：

1. 新接入请优先使用本文档中的标准字段
2. 旧页面可继续使用兼容字段
3. 导出类接口返回文件流，不走普通 JSON 列表渲染

## 2. 任务环节枚举

| 值 | 中文 |
| --- | --- |
| `measure` | 量尺 |
| `install` | 安装 |
| `ironing` | 熨烫 |
| `cleaning` | 除尘除螨 |

## 3. 经销商端任务状态说明

涉及页面：

1. 任务列表
2. 任务详情
3. 分配任务页

状态说明：

| 内部状态 | 页面文案 | 说明 |
| --- | --- | --- |
| `pending_assign` | 待执行 | 还未分配师傅，可进入分配任务页 |
| `pending_execute` | 待执行 | 已分配师傅，待师傅开始执行 |
| `executing` | 进行中 | 师傅已开始执行 |

前端判断字段：

| 字段 | 说明 |
| --- | --- |
| `can_assign` | `true` 表示当前任务可分配，进入分配任务页 |
| `can_reassign` | `true` 表示当前任务可重派 |

进度追踪说明：

1. `pending_assign` 时，进度追踪全部可置灰
2. `pending_execute` 时，任务已分派节点会点亮并带时间，其余节点可置灰
3. `executing` 后，才会逐步出现到达现场、现场照片、完成环节的时间
4. 分配任务页对应的任务状态是 `pending_assign`

### 3.1 分配任务页服务类型筛选

可用师傅单服务类型查询：

```http
GET /api/technicians/available?store_id=3&service_type=install
```

说明：

1. 后端已按师傅服务能力 `service_types` 精确过滤
2. `service_type=install` 只返回 `service_types` 包含 `install` 的师傅

可用师傅多服务类型分组查询：

```http
GET /api/technicians/available/grouped?store_id=3&service_types=install,ironing
```

返回结构：

```json
{
  "groups": [
    {
      "service_type": "install",
      "service_type_text": "安装服务",
      "technicians": []
    },
    {
      "service_type": "ironing",
      "service_type_text": "熨烫服务",
      "technicians": []
    }
  ]
}
```

分配接口：

```http
POST /api/tasks/{id}/assign
```

兼容旧请求：

```json
{
  "technician_id": 28,
  "assign_reason": "任务分配"
}
```

单环节分配：

```json
{
  "service_type": "install",
  "technician_id": 28,
  "assign_reason": "任务分配"
}
```

多环节批量分配：

```json
{
  "assignments": [
    { "service_type": "install", "technician_id": 28 },
    { "service_type": "ironing", "technician_id": 29 }
  ],
  "assign_reason": "任务分配"
}
```

说明：

1. `service_item_id` 也支持，且优先于 `service_type`
2. 后端会校验服务环节属于当前任务
3. 后端会校验师傅属于当前门店并具备对应 `service_types` 服务能力

## 4. 任务列表导出

- 接口：`GET /tasks/export`
- 用途：后台任务列表批量导出
- 查询参数：与 `GET /tasks` 完全一致
- 返回类型：`text/csv`

前端处理：

1. 按文件流下载处理
2. 文件名：`tasks-export.csv`

导出列：

| 字段 | 说明 |
| --- | --- |
| `task_id` | 任务 ID |
| `task_no` | 任务号 |
| `service_type` | 主服务环节 |
| `service_items` | 多环节中文组合 |
| `task_status` | 任务状态中文 |
| `display_status` | 页面状态中文 |
| `review_status` | 评价状态中文 |
| `score_status` | 评分状态中文 |
| `appointment_time` | 预约时间 |
| `customer_name` | 客户姓名 |
| `customer_mobile` | 客户手机号 |
| `store_name` | 门店名称 |
| `dealer_name` | 经销商名称 |
| `technician_name` | 师傅姓名 |
| `technician_mobile` | 师傅手机号 |
| `is_overdue` | 是否逾期，值为 `是/否` |
| `task_tags` | 标签，`|` 拼接 |

- 接口：`POST /users/batch-delete`

```json
{
  "user_ids": [6, 7]
}
```

兼容旧请求：

```json
{
  "ids": ["6", "7"]
}
```

说明：

1. 新页面请使用 `user_ids`
2. 老页面继续传 `ids` 也可用
3. `ids` 支持字符串数组和数字数组

## 8. 技师新增

- 接口：`POST /technicians`

推荐请求：

```json
{
  "name": "陈师傅",
  "mobile": "12364565245",
  "password": "123456",
  "store_id": 23,
  "service_types": ["install", "ironing"]
}
```

兼容旧请求：

```json
{
  "name": "陈师傅",
  "mobile": "12364565245",
  "store_ids": [23],
  "role_names": ["安装", "熨烫"]
}
```

兼容规则：

1. `password` 允许不传，不传默认 `123456`
2. `store_ids` 会兼容为 `store_id`，取第一个值
3. `role_names` 会兼容为 `service_types`
4. `service_types/role_names` 支持中英文混传

服务能力映射：

| 前端可传值 | 后端标准值 |
| --- | --- |
| `量尺` / `measure` | `measure` |
| `安装` / `install` | `install` |
| `熨烫` / `ironing` | `ironing` |
| `除尘除螨` / `cleaning` | `cleaning` |

## 11. 客户模糊查询

- 接口：`GET /customers`

支持查询参数：

| 字段 | 说明 |
| --- | --- |
| `mobile` | 按手机号模糊匹配 |
| `name` | 按客户姓名模糊匹配 |

## 12. 客户接口新增字段

涉及接口：

1. `GET /customers`

| 字段 | 类型 | 说明 |

## 14. 去评分接口

- 接口：`POST /tasks/{id}/hq-score`
- 用途：总部对任务评分

请求结构：

```json
{
  "items": [
    {
      "service_type": "install",
      "score": 90,
      "deduction_reason": ""
    }
  ],
  "score_remark": "总部检核通过"
}
```

说明：

1. `items` 不能为空
2. `score` 范围 `0-100`
3. `service_type` 必须和任务真实环节一致

## 15. 评分导入

- 接口：`POST /hq/scores/import`
- 支持：`csv/xlsx`

导入列：

| 字段 | 说明 |
| --- | --- |
| `task_id` | 任务 ID |
| `service_type` | 服务环节 |
| `score` | 分值 |
| `deduction_reason` | 扣分原因，可空 |
| `score_remark` | 评分备注，可空 |

后端校验：

1. 任务必须存在
2. 任务状态必须是 `pending_hq_score`
3. 同一任务不能重复评分
4. `service_type` 必须属于该任务真实环节
5. 成功后任务状态更新为 `completed`

## 18. 角色管理

适用页面：

1. 后台角色列表
2. 后台新增/编辑角色
3. 后台权限树展示

涉及接口：

1. `GET /system/roles`
2. `GET /system/roles/{id}`
3. `POST /system/roles`
4. `PATCH /system/roles/{id}`
5. `DELETE /system/roles/{id}`
6. `GET /system/permission-tree`

角色列表返回字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 数字主键 ID |
| `role_code` | 角色编码，可直接作为页面角色 ID 展示 |
| `role_name` | 角色名称 |
| `name` | 兼容字段，等于 `role_name` |
| `remark` | 备注 |
| `status` | `active/disabled` |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |
| `permission_ids` | 权限 ID 列表 |
| `permission_keys` | 权限编码列表，前端权限树勾选建议直接用这个 |

新增角色请求示例：

```json
{
  "role_name": "经销商主管",
  "permission_keys": [
    "workspace",
    "tasks",
    "tasks:list",
    "tasks:list:create",
    "users",
    "users:customers"
  ],
  "remark": "可维护客户和师傅信息",
  "status": "active"
}
```

说明：

1. `role_name` 与 `name` 二选一即可
2. `role_code` 可不传，不传后端自动生成如 `ROLE-001`
3. 权限可传 `permission_keys`，也可传 `permission_ids`
4. `status` 支持 `active/disabled`

权限树返回结构：

| 字段 | 说明 |
| --- | --- |
| `id` | 权限 ID |
| `key` | 权限编码，前端 Tree 建议直接使用 |
| `title` | 权限名称，前端 Tree 标题直接使用 |
| `permission_code` | 权限编码 |
| `permission_name` | 权限名称 |
| `permission_type` | 权限类型 |
| `parent_id` | 父节点 ID |
| `sort_no` | 排序号 |
| `children` | 子节点数组 |
