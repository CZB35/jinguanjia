# 后台端接口文档

## 1. 基本信息

- 端：后台端（总部检核 + 管理后台）
- 接口前缀：`/api`
- 当前状态：`已实现` + `已完成冒烟测试`

## 2. 通用返回结构

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | number | 业务码，`0` 表示成功 |
| `message` | string | 返回消息 |
| `data` | object | 业务数据 |
| `request_id` | string | 请求追踪 ID |

## 3. 页面与接口

### 3.1 登录与角色

- `POST /auth/login/password`
- `POST /auth/login/code`
- `POST /auth/code/send`
- `POST /auth/refresh`
- `POST /auth/logout`
- `GET /auth/me`
- `POST /auth/switch-role`

状态：全部 `已实现` `已测试`

登录补充说明：

1. 后台端也可以不传 `role_code`，后端会按优先级选默认角色
2. 如果账号支持多个角色，响应会返回：
   - `roles`
   - `current_role`
   - `switchable`
3. 访问受保护接口时，请求头格式必须是：`Authorization: Bearer <access_token>`
4. 如果后台登录页固定区分管理员角色，也可以显式传 `role_code=super_admin`

评分导入字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `task_id` | number | 任务 ID |
| `service_type` | string | 服务环节 |
| `score` | number | 分值 |
| `deduction_reason` | string | 扣分原因，可空 |
| `score_remark` | string | 评分备注，可空 |

评分导入逻辑：

1. 支持 `csv/xlsx`
2. 任务必须存在
3. 任务状态必须是 `pending_hq_score`
4. 任务不能已评分
5. `service_type` 必须属于该任务真实环节
6. 导入成功后写入 `hq_score`、`hq_score_item`，并把任务更新为 `completed`

用户批量删除兼容说明：

1. 标准请求字段为 `user_ids`
2. 同时兼容旧字段 `ids`
3. `ids` 支持字符串数组，例如 `{"ids":["6","7"]}`
