# 服务号通知后端对接方案

本文档说明当前后端已补充的服务号通知基础能力，以及后续前端/运维需要配合的内容。

## 1. 当前方案定位

当前采用：

- 单实例部署
- 不使用 Redis
- 站内通知继续保留
- 服务号通知异步发送
- `access_token` 进程内存缓存
- 通知投递队列落数据库

核心目标：

- 不阻塞主业务请求
- 先落库，再异步发微信
- 主请求只做业务处理 + 通知入队

## 2. 已补充的数据结构

### 2.1 用户微信绑定字段

已在 `user` 表新增：

- `wechat_openid`
- `wechat_unionid`
- `wechat_subscribe`
- `wechat_bind_at`
- `wechat_subscribe_updated_at`

作用：

- 存储服务号 `openid`
- 记录绑定时间和关注状态

### 2.2 通知投递表

新增表：`notice_delivery`

关键字段：

- `notice_id`
- `channel`
- `receiver_id`
- `receiver_openid`
- `biz_type`
- `biz_id`
- `template_code`
- `payload_json`
- `status`
- `attempt_count`
- `next_retry_at`
- `provider_message_id`
- `error_message`
- `sent_at`

作用：

- 站内消息与微信消息分离管理
- 支持重试、失败记录、投递状态追踪

## 3. 已补充的服务端能力

### 3.1 服务号绑定地址生成

接口：

- `GET /api/me/wechat-bind-url`

作用：

- 生成服务号 OAuth 绑定地址
- 当前登录用户可据此跳服务号授权

### 3.2 当前绑定状态查询

接口：

- `GET /api/me/wechat-binding`

返回：

- 是否已绑定
- 当前 `openid`
- 是否关注
- 绑定时间

### 3.3 服务号回调绑定

接口：

- `GET /api/wechat/service-account/callback`

作用：

- 微信服务号 OAuth 回调
- 服务端根据 `state` 识别用户
- 将服务号 `openid` 绑定到当前用户

## 4. 通知发送链路

### 当前流程

1. 业务代码调用 `notify::create_notice()`
2. 落库 `notice`
3. 如果用户已绑定服务号且开启微信通知，则写 `notice_delivery`
4. 后台 worker 轮询 `notice_delivery`
5. 调微信模板消息发送接口
6. 更新发送状态

### 说明

- 主业务请求不等待微信返回
- 所以不会明显拖慢：
  - 分派任务
  - 提交任务
  - 评价
  - 总部评分

## 5. 服务号通知配置项

当前建议通过 `system_config` 维护。

### 服务号基础配置

- `wechat.service_account.appid`
- `wechat.service_account.secret`
- `wechat.service_account.bind_redirect_uri`

### 发送控制配置

- `wechat.notify.enabled`
- `wechat.notify.retry_limit`
- `wechat.notify.retry_interval_seconds`

### 模板配置

按 `biz_type` 维护：

- `wechat.template.task_assign.template_id`
- `wechat.template.task_assign.page_path`
- `wechat.template.task_assign.miniprogram_appid`

- `wechat.template.task_reassign.template_id`
- `wechat.template.task_submit.template_id`
- `wechat.template.task_review_reminder.template_id`
- `wechat.template.hq_score_done.template_id`

## 6. 当前支持的业务通知入队

当前 `notice` / `biz_type` 体系主要包括：

- `task_assign`
- `task_reassign`
- `task_submit`
- `dealer_review_done`
- `hq_score_done`
- `customer_review_link`
- `task_review_reminder`

后端会以 `biz_type` 作为 `template_code` 默认值写入 `notice_delivery`。

## 7. 幂等与重试策略

### 幂等

当前 `notice_delivery` 通过唯一键约束：

- `uk_notice_delivery_notice_channel` = (`notice_id`, `channel`)

作用：

- 同一条站内通知不会重复入队同一渠道

### 重试

当前 worker 规则：

- 只处理 `status = pending`
- 单次最多处理一批小量记录
- 失败后根据：
  - `attempt_count`
  - `retry_limit`
  - `next_retry_at`
 进行回退或终态标记

## 8. 还需要前端/运维配合的内容

### 前端需要

1. 在个人设置或系统设置页提供“绑定服务号”入口
2. 登录后可读取：
   - `GET /api/me/wechat-binding`
3. 用户点击绑定时跳转：
   - `GET /api/me/wechat-bind-url` 返回的 `bind_url`
4. 保留通知开关：
   - `wechat_enabled`

### 运维需要

1. 在后台或脚本中写入 `system_config`：
   - 服务号 `appid`
   - `secret`
   - 回调地址
   - 各模板 ID
2. 确保公网可访问微信回调地址
3. 确保服务端可访问微信开放接口

## 9. 当前仍需补充的地方

3. 服务号关注状态同步/取消关注处理
4. 失败投递查询与手动重发接口
