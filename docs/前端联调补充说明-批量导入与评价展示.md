## 适用范围

本文补充本轮新增的两类能力：

- 批量导入经销商 / 客户 / 门店
- 任务详情 / 环节记录详情新增客户评价、经销商评价模块

所有接口默认都挂在 `/api` 下。

## 1. 批量导入接口

### 1.1 批量导入经销商账号

接口：

```http
POST /dealers/import
Content-Type: multipart/form-data
```

上传字段：

- 文件字段名：`file`

支持格式：

- `csv`
- `xls`
- `xlsx`

模板字段：

- `姓名`
- `手机号`
- `密码`
- `所属门店`
- `状态`

说明：

- 如果导入文件里没有角色列，后端会自动按 `dealer` 处理
- 经销商账号必须且只能绑定一个门店
- `所属门店` 填门店名称或门店编码，不要填数据库 ID
- `状态` 支持：
  - `启用`
  - `禁用`
  - `enabled`
  - `disabled`
  - `active`
  - `inactive`
- `状态` 可留空，留空默认按 `启用` 导入

### 1.2 批量导入客户

接口：

```http
POST /customers/import
Content-Type: multipart/form-data
```

模板字段：

- `客户姓名`
- `客户手机号`
- `客户来源`
- `所属门店`
- `省`
- `市`
- `区`
- `详细地址`
- `备注`

说明：

- 客户手机号不能重复
- `所属门店` 如果填写，后端会按门店名称或门店编码匹配门店
- `详细地址` 可为空；为空时只创建客户，不创建默认地址
- `客户来源` 建议直接填中文名称，例如 `手工录入`
- `客户来源` 也兼容来源编码或来源名称
- 如果不传 `客户来源`，默认按 `手工录入` 处理

### 1.3 批量导入门店

接口：

```http
POST /stores/import
Content-Type: multipart/form-data
```

模板字段：

- `门店名称`
- `门店编码`
- `省`
- `市`
- `区`
- `详细地址`
- `联系人`
- `联系电话`
- `营业时间`
- `备注`
- `状态`

说明：

- `门店名称` 不能为空，且不能重复
- `门店编码` 可留空；如果填写，不能重复
- `状态` 支持：
  - `启用`
  - `禁用`
  - `enabled`
  - `disabled`
  - `active`
  - `inactive`
- `状态` 可留空，留空默认按 `启用` 导入

## 2. 导入模板下载

统一模板下载接口：

```http
GET /users/import-template
```

### 2.1 下载后台账号模板

```http
GET /users/import-template
```

### 2.2 下载经销商模板

```http
GET /users/import-template?role_code=dealer
```

### 2.3 下载客户模板

```http
GET /users/import-template?import_type=customer
```

### 2.4 下载门店模板

```http
GET /users/import-template?import_type=store
```

当前返回文件名：

- 后台账号：`users-import-template.xlsx`
- 经销商：`dealers-import-template.xlsx`
- 客户：`customers-import-template.xlsx`
- 门店：`stores-import-template.xlsx`

说明：

- 模板文件已改成 `xlsx`，不再出现 `sep=` 这一行
- 模板第一页是示例数据，第二页是填写说明

## 3. 导入返回结构

导入接口统一返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "success_count": 10,
    "failed_count": 2,
    "errors": [
      "第3行手机号已存在: 13800001111",
      "第5行所属门店不存在: 西湖一店"
    ],
    "error_file_name": "customers-import-errors.xlsx",
    "error_file_base64": "UEsDB..."
  }
}
```

前端建议：

- 导入完成后弹窗展示：成功条数 / 失败条数
- 如果 `errors` 不为空，支持展开查看失败明细
- 如果 `error_file_base64` 不为空，前端应直接转成文件并自动下载 `error_file_name`
- 失败明细文件为 `xlsx`，每一行会带原始数据和失败原因

前端处理建议：

```js
const binary = atob(data.error_file_base64)
const bytes = Uint8Array.from(binary, (char) => char.charCodeAt(0))
const blob = new Blob([bytes], { type: 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet' })
```

## 4. 任务详情新增评价模块字段

接口：

```http
GET /tasks/{id}
```

当前详情返回中新增：

- `dealer_review`
- `customer_review`

### 4.1 经销商评价

结构：

```json
{
  "star": 5,
  "tags": ["准时", "专业"],
  "content": "服务很好，处理很及时",
  "created_at": "2026-06-15 10:20:30"
}
```

重点字段：

- 评价内容：`dealer_review.content`

### 4.2 客户评价

结构：

```json
{
  "star": 5,
  "tags": ["满意", "干净整洁"],
  "content": "师傅很细心，整体很满意",
  "images": [
    {
      "id": 1,
      "file_url": "/uploads/customer-reviews/xxx.jpg"
    }
  ],
  "created_at": "2026-06-15 10:30:12"
}
```

重点字段：

- 评价内容：`customer_review.content`

## 5. 环节记录详情新增评价模块字段

接口：

```http
GET /hq/review/tasks/{id}
```

当前返回中新增：

- `dealer_review`
- `customer_review`

字段结构与任务详情保持一致。

前端建议：

- 在“服务轨迹 / 服务轨迹下方”新增两个模块：
  - `经销商评价`
  - `客户评价`
- 如果对应字段为 `null`，可显示：

```text
暂无评价
```
