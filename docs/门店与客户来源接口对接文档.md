# 门店、师傅与客户来源接口对接文档

接口统一前缀：`/api`

统一响应结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "uuid"
}
```

## 1. 角色范围说明

- 经销商端：只能看到和操作自己所属门店的数据
- 师傅端：当前没有本次新增的门店管理、师傅管理、客户来源管理接口
- 后台端：可查看和维护全部门店、全部师傅、全部客户来源

## 1.1 主链路门店来源

适用端：

- 经销商端
- 师傅端
- 后台端

接口：

- `GET /me/profile`

当前返回中可直接使用这些门店字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `store_id` | number | 当前主门店 ID，前端主链路可直接用这个字段 |
| `store_ids` | number[] | 当前账号关联门店 ID 列表 |
| `primary_store_id` | number | 当前主门店 ID，与 `primary_store_name` 对应 |
| `primary_store_name` | string | 当前主门店名称 |
| `store_names` | string[] | 当前账号关联门店名称列表 |

说明：

- 经销商账号当前按单门店约束，`store_id`、`primary_store_id`、`store_ids[0]` 应该指向同一个门店
- 经销商端“客户查询/新增客户 -> 创建任务 -> 选择师傅”这条链路，建议统一使用 `GET /me/profile` 返回的 `store_id`

## 2. 门店接口

### 2.1 `GET /stores`

适用端：

- 经销商端
- 后台端

查询参数：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `page` | number | 页码，默认 `1` |
| `page_size` | number | 每页条数，默认 `20` |
| `name` | string | 门店名称模糊查询 |
| `store_name` | string | 兼容旧字段，等价于 `name` |
| `code` | string | 门店编码模糊查询 |
| `contact_mobile` | string | 联系电话模糊查询 |
| `status` | string | `enabled/disabled`，兼容 `active/inactive` |

返回字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `items[].id` | number | 门店 ID |
| `items[].name` | string | 门店名称 |
| `items[].store_name` | string | 门店名称，兼容旧前端字段 |
| `items[].code` | string | 门店编码 |
| `items[].contact_name` | string | 联系人 |
| `items[].contact_mobile` | string | 联系电话 |
| `items[].province` | string | 省 |
| `items[].city` | string | 市 |
| `items[].district` | string | 区/县 |
| `items[].region_text` | string | 所属地区，格式如 `浙江省/杭州市/西湖区` |
| `items[].address` | string | 门店地址 |
| `items[].remark` | string | 备注 |
| `items[].business_hours` | string | 营业时间 |
| `items[].status` | string | 实际返回为 `enabled/disabled` |
| `items[].technician_count` | number | 门店师傅数量 |
| `items[].customer_count` | number | 门店客户数量 |
| `items[].completed_task_count` | number | 已完成任务数 |
| `items[].completion_rate` | number | 完成率 |
| `total` | number | 总数 |
| `page` | number | 当前页 |
| `page_size` | number | 每页条数 |

范围说明：

- 后台端返回全部门店
- 经销商端只返回当前经销商所属门店

### 2.2 `GET /stores/{id}`

适用端：

- 经销商端
- 后台端

返回字段与门店列表单项一致。

范围说明：

- 后台端可查看任意门店
- 经销商端只能查看自己所属门店

### 2.3 `POST /stores`

适用端：

- 后台端

请求体：

```json
{
  "name": "北京朝阳门店",
  "code": "BJ-CY-001",
  "contact_name": "王店长",
  "contact_mobile": "13800001234",
  "province": "北京市",
  "city": "北京市",
  "district": "朝阳区",
  "address": "北京市朝阳区xxx",
  "remark": "旗舰店",
  "business_hours": "09:00-18:00",
  "status": "active"
}
```

说明：

- `name` 与 `store_name` 二选一即可，后端统一存为 `store_name`
- 支持 `province`、`city`、`district` 三个地区字段
- `status` 支持 `active/inactive`，也支持 `enabled/disabled`
- 实际存储值统一为 `enabled/disabled`
- `code` 可为空，但如果传值必须唯一

### 2.4 `PATCH /stores/{id}`

适用端：

- 经销商端
- 后台端

请求体字段与新增一致，全部为可选字段。

范围说明：

- 后台端可修改任意门店
- 经销商端只能修改自己所属门店

### 2.5 `PATCH /stores/{id}/status`

适用端：

- 后台端

请求体：

```json
{
  "status": "active"
}
```

说明：

- 支持 `active/inactive`
- 支持 `enabled/disabled`
- 实际存储值统一为 `enabled/disabled`

### 2.6 `DELETE /stores/{id}`

适用端：

- 后台端

说明：

- 如果门店已被以下业务数据引用，则不允许删除
- `task.store_id`
- `user_store.store_id`
- `customer.primary_store_id`
- 删除失败时会返回冲突错误，避免影响历史任务和主流程数据

## 3. 师傅接口

### 3.1 `GET /technicians`

适用端：

- 经销商端
- 后台端

查询参数：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 师傅姓名模糊查询 |
| `mobile` | string | 联系电话模糊查询 |
| `service_type` | string | 专业技能筛选，支持 `measure/install/ironing/cleaning` |

范围说明：

- 后台端返回全部师傅
- 经销商端只返回自己所属门店下的师傅

### 3.2 `GET /technicians/available`

适用端：

- 经销商端
- 后台端

查询参数：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `store_id` | number | 门店 ID |
| `service_type` | string | 专业技能 |

范围说明：

- 后台端可按任意门店查询可选师傅
- 经销商端只能按自己所属门店查询可选师傅

### 3.2.1 `GET /customers/search-by-mobile`

适用端：

- 经销商端
- 后台端

查询参数：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `mobile` | string | 联系电话关键字，支持模糊搜索 |

说明：

- 可用于“分派任务时输入联系电话，模糊查找客户并自动带出客户信息”
- 经销商端只会返回自己所属门店范围内的客户
- 后台端可返回全量匹配客户

### 3.3 `GET /technicians/{id}`

适用端：

- 经销商端
- 后台端

范围说明：

- 后台端可查看任意师傅
- 经销商端只能查看自己所属门店下的师傅

### 3.4 `POST /technicians`

适用端：

- 经销商端
- 后台端

请求体：

```json
{
  "name": "张师傅",
  "mobile": "13800009999",
  "id_card": "110101199001011234",
  "emergency_contact_name": "李四",
  "emergency_contact_mobile": "13800008888",
  "service_types": ["install", "measure"],
  "store_id": 1
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 师傅姓名，必填 |
| `mobile` | string | 联系电话，必填 |
| `password` | string | 密码，可选；不传默认 `123456` |
| `id_card` | string | 身份证号 |
| `emergency_contact_name` | string | 紧急联系人 |
| `emergency_contact_mobile` | string | 紧急联系电话 |
| `service_types` | string[] | 专业技能，必填；支持多选 |
| `store_id` | number | 所属门店 |

专业技能可选值：

- `measure`
- `install`
- `ironing`
- `cleaning`

重要说明：

- 一个师傅账号必须且只能绑定一个门店
- 后台端新增师傅时，需要明确传 `store_id`
- 经销商端新增师傅时，后端会自动把师傅绑定到“当前经销商所属门店”
- 经销商端前端页面可以保留所属门店展示，但提交时不需要依赖用户手动切换到别的门店

### 3.5 `PATCH /technicians/{id}`

适用端：

- 经销商端
- 后台端

请求体字段与新增基本一致，但全部为可选字段。

说明：

- `service_types` 支持多选
- `store_id` 仍为单门店绑定
- 经销商端只能修改自己所属门店下的师傅

### 3.6 `PATCH /technicians/{id}/status`

适用端：

- 经销商端
- 后台端

请求体：

```json
{
  "status": "enabled"
}
```

说明：

- 只支持 `enabled/disabled`
- 经销商端只能操作自己所属门店下的师傅

### 3.7 `GET /technicians/{id}/performance`

适用端：

- 经销商端
- 后台端

范围说明：

- 后台端可查看任意师傅绩效
- 经销商端只能查看自己所属门店下的师傅绩效

| 字段 | 类型 | 说明 |

返回字段：

| 字段 | 类型 | 说明 |

| `items[].name` | string | 来源名称 |
| `items[].code` | string | 来源编码 |
| `items[].sort` | number | 排序号 |
| `items[].remark` | string | 备注 |
| `items[].status` | string | 实际返回为 `enabled/disabled` |
| `total` | number | 总数 |
| `page` | number | 当前页 |
| `page_size` | number | 每页条数 |

### 4.2 `GET /customer-sources/{id}`

适用端：

- 后台端

### 4.3 `POST /customer-sources`

适用端：

- 后台端

请求体：

```json
{

  "code": "STORE_INPUT",
  "sort": 10,
  "remark": "门店手动建档",

```

说明：

- `sort` 和 `sort_no` 都支持
- `code` 必须唯一
- `status` 支持 `active/inactive`，实际存储为 `enabled/disabled`

### 4.4 `PATCH /customer-sources/{id}`

适用端：

- 后台端

请求体字段与新增一致，全部为可选字段。

### 4.5 `DELETE /customer-sources/{id}`

适用端：

- 后台端

成功返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "ok": true
  },
  "request_id": "uuid"

```

## 5. 后台账号绑定规则

适用端：

- 后台端

涉及接口：

- `POST /users`
- `PATCH /users/{id}`

规则：

- 经销商账号必须且只能绑定一个门店
- 师傅账号必须且只能绑定一个门店
- 一个门店可以绑定多个经销商
- 一个门店可以绑定多个师傅
- 后台如果给经销商或师傅账号传 `store_ids` 为 `0` 个或多个，后端会直接报错

## 6. 兼容说明

- 门店接口保留了旧字段 `store_name`
- 门店接口新增兼容字段 `name`
- 门店状态兼容 `active/inactive` 与 `enabled/disabled`
- 客户来源接口状态兼容 `active/inactive` 与 `enabled/disabled`
- 当前客户建档接口仍使用 `source`
- 当前建单接口仍使用 `customer_source`
- 客户与任务主流程不会因为新增 `customer-sources` 接口而被强制切换

## 7. 上线前准备

- 为 `store` 表增加 `remark`
- 为 `store.code` 增加唯一索引
