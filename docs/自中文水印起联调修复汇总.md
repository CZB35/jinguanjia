# 自中文水印起联调修复汇总

本文档只汇总从“现场实据中文字体水印”开始，到当前这一轮联调收尾为止的改动。

适用范围：

- 后端联调回溯
- 测试回归核对
- 替代最近几份阶段性临时说明文档

## 1. 现场实据图片水印升级

涉及文件：

- `Cargo.toml`
- `Cargo.lock`
- `src/routes/files.rs`
- `src/assets/fonts/simhei.ttf`

修复内容：

- 现场实据图片不再只压底部像素字。
- 后端现在优先使用仓库内字体 `simhei.ttf` 渲染中文可读水印。
- 水印信息改为业务上下文，而不是只有任务 ID。

当前水印内容包含：

- 门店
- 服务地址
- 客户姓名
- 脱敏手机号
- 服务环节
- 时间

说明：

- 如果字体加载失败，仍会回退到旧的位图文本水印逻辑。
- 水印文字同时仍会写入 `evidence.watermark_text` 作为兜底记录。

## 2. 个人中心完成统计口径修复

涉及文件：

- `src/routes/me.rs`

修复内容：

- 经销商/师傅个人中心的完成数与本月完成数，不再只统计 `completed`。
- 现在统一按以下状态计入“完成”：
  - `pending_hq_score`
  - `completed`
  - `closed`

影响接口：

- `GET /api/me/profile`

## 3. 可选师傅列表统计改为真实数据

涉及文件：

- `src/routes/technicians.rs`

原问题：

- 可选师傅列表虽然能返回师傅，但评分、完单数、待处理数、工作状态被写死成 `0` 或空值。

修复内容：

- `GET /api/technicians/available`
- `GET /api/technicians/available/grouped`

现在返回真实：

- `average_score`
- `completed_order_count`
- `pending_order_count`
- `current_task_no`
- `current_task_status`
- `work_status`
- `score_count`

统计口径复用现有师傅聚合逻辑，和师傅列表页保持一致。

## 4. 客户服务历史补齐前端实际在读字段

涉及文件：

- `src/routes/customers.rs`

修复内容：

- `GET /api/customers/{id}/service-history` 现在补充：
  - `appointment_time`
  - `store_name`
- 同时保留原有：
  - `task_id`
  - `task_no`
  - `service_type`
  - `task_status`
  - `technician_name`
  - `service_items`
  - `service_date`

补充兼容：

- `GET /api/customers/{id}` 顶层新增 `service_history`
- `GET /api/customers/search-by-mobile` 的每个客户项新增 `service_history`

作用：

- 后台客户详情页可直接显示服务历史。
- 小程序客户查询/客户详情页如果直接消费客户对象，也能拿到历史数据源。

## 5. 任务详情时间显示改为具体时间优先

涉及文件：

- `src/routes/tasks.rs`

原问题：

- 任务详情页仍可能显示 `上午 / 下午 / 晚上` 这类粗粒度文案。

修复内容：

- `GET /api/tasks/{id}` 返回的 `service_time_slot` 现在优先按 `appointment_time` 格式化为具体时分。
- 当前口径：优先返回 `HH:MM`；只有缺少预约时间时，才回退原 `service_time_slot`。

同时补齐：

- 任务详情里的客户地址改为完整地址。
- 现在会拼接：`province + city + district + address`。

影响页面：

- 小程序任务详情
- 后台任务详情
- 经销商/HQ 侧任何直接读取 `service_time_slot` 的详情页

## 6. HQ 评分详情页时间与地址修复

涉及文件：

- `src/routes/hq_review.rs`

修复内容：

- `GET /api/hq/review/tasks/{id}` 的 `customer_address` 改为完整地址。
- `service_time_slot` 改为具体时间优先，口径与任务详情保持一致。

解决的问题：

- 服务地址不详细
- 服务时间仍显示时段词而不是具体时间

## 7. 服务标准接口补结构化 items

涉及文件：

- `src/routes/standards.rs`

原问题：

- 一些前端页面优先读取 `items` 数组渲染标准卡片。
- 后端原先只返回 `content` 文本，页面会退回原始 JSON/文本预览，容易被误判成“乱码”。

修复内容：

- `GET /api/standards/{serviceType}` 现在除了原字段外，新增 `items`。
- `items` 会根据 `content` 或项目设置里的 `requirement_content` 自动拆分生成。

当前返回结构包含：

- `service_type`
- `title`
- `content`
- `example_file_url`
- `warm_tip_content`
- `version_no`
- `items`

`items[]` 字段：

- `id`
- `title`
- `content`

说明：

- 保留原有 `content`，兼容旧前端。
- 新前端可优先用 `items` 直接渲染结构化标准列表。
