## 3. 页面与接口

### 3.1 登录页

#### 3.1.1 密码登录

- 接口：`POST /auth/login/password`
- 状态：`已实现` `已测试`

说明：

1. 小程序端登录时 `role_code` 可不传
2. 后端会按默认优先级自动选择角色：`dealer -> technician -> hq_reviewer -> super_admin`
3. 如果账号有多个角色，返回 `switchable=true`，前端显示角色切换
4. 如果当前端是经销商独立登录页，也可以固定传 `role_code=dealer`

请求字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `mobile` | string | 手机号 |
| `password` | string | 密码 |
| `role_code` | string | 可选，指定角色 |

返回字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `access_token` | string | 访问令牌 |
| `refresh_token` | string | 刷新令牌 |
| `token_type` | string | 固定 `Bearer` |
| `expires_in` | number | 过期秒数 |
| `user.id` | number | 用户 ID |
| `user.name` | string | 用户名称 |
| `user.mobile` | string | 手机号 |
| `user.roles` | string[] | 角色编码列表 |
| `user.current_role` | string | 当前角色 |
| `user.switchable` | boolean | 是否支持角色切换 |
| `user.status` | string | 账号状态 |

请求头说明：

1. 后端返回的是纯 `access_token`
2. 前端调用受保护接口时，必须在请求头中带：`Authorization: Bearer <access_token>`

#### 3.1.2 验证码发送

- 状态：`已实现` `已测试`

请求字段：

| 字段 | 类型 | 说明 |

返回字段：

#### 3.1.3 验证码登录

- 接口：`POST /auth/login/code`
- 状态：`已实现` `已测试`

说明：

1. 仅允许后台已创建账号使用验证码登录
2. 请求验证码时会校验手机号是否已存在系统账号

请求字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `mobile` | string | 手机号 |
| `code` | string | 验证码 |
| `role_code` | string | 可选，指定角色 |

返回字段：与密码登录一致。
