# 任务重派与师傅、门店编辑前端接口对接文档

## 一、接口总览

本次没有修改任何接口地址或请求方法。

| 功能 | 请求方法 | 完整接口地址 |
| --- | --- | --- |
| 任务重新分派 | `POST` | `/api/tasks/{id}/reassign` |
| 重新读取任务详情 | `GET` | `/api/tasks/{id}` |
| 重新读取任务详情兼容地址 | `GET` | `/api/tasks/{id}/detail` |
| 编辑师傅 | `PATCH` | `/api/technicians/{id}` |
| 获取师傅详情 | `GET` | `/api/technicians/{id}` |
| 编辑门店 | `PATCH` | `/api/stores/{id}` |
| 获取门店详情 | `GET` | `/api/stores/{id}` |

请求基础地址按当前环境配置，例如：

```text
https://service.ryds.cn
```

完整生产接口示例：

```text
https://service.ryds.cn/api/technicians/4
```

## 二、通用请求说明

### 2.1 请求头

```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

### 2.2 成功响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "uuid"
}
```

| 参数 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `code` | number | 否 | 成功固定为 `0` |
| `message` | string | 否 | 成功固定为 `success` |
| `data` | object | 否 | 当前接口的业务数据 |
| `request_id` | string | 否 | 请求追踪 ID，报错排查时使用 |

### 2.3 失败响应结构

```json
{
  "code": 1001,
  "message": "具体错误信息",
  "data": null,
  "request_id": "uuid"
}
```

| HTTP 状态 | 业务码 | 说明 |
| --- | --- | --- |
| `400` | `1001` | 请求参数、格式或必填校验失败 |
| `401` | `1006` | 未登录或登录已失效 |
| `403` | `1007` | 当前账号无权限 |
| `404` | `2001` | 数据不存在 |
| `409` | `2002` | 状态冲突、并发冲突或唯一性冲突 |
| `500` | `9000` | 后端内部错误 |

前端业务判断使用 HTTP 状态和 `code`，`message` 只用于页面提示。

## 三、任务重新分派接口

### 3.1 接口信息

```http
POST /api/tasks/{id}/reassign
```

用途：

- 整单重新分派给一个师傅。
- 重新分派给当前同一位师傅。
- 整单重派时修改当前任务的服务类型。
- 整单重派时同步修改任务资料。
- 单个服务环节重新分派。
- 多个服务环节批量重新分派。

允许角色：`dealer`、`hq_reviewer`、`super_admin`。

### 3.2 路径参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | number | 是 | URL 中的任务 ID |

### 3.3 请求体参数

#### 3.3.1 分派参数

以下字段名、驼峰别名与首次分派 `POST /api/tasks/{id}/assign` 相同。注意：首次分派可用顶层 `service_type` 定位环节；重新分派中顶层 `service_type` 表示整单目标类型，两者模式语义不同。

| 参数 | 类型 | 必填 | 兼容参数名 | 说明 |
| --- | --- | --- | --- | --- |
| `technician_id` | number | 条件必填 | `technicianId` | 整单或单环节重派的目标师傅 ID，可以与当前师傅相同；批量模式省略 |
| `service_type` | string | 否 | `serviceType` | **整单重派时表示修改后的任务服务类型**；只支持 `measure/install/ironing/cleaning`；未传表示保留原类型 |
| `service_item_id` | number | 否 | `serviceItemId` | 单环节重派的服务环节 ID；只要传入此字段就进入单环节模式 |
| `assignments` | object[] | 否 | 无 | 多环节批量重派数组 |
| `assign_reason` | string | 否 | `assignReason` | 重派原因；未传或空白时默认“重新分派” |

`assignments[]` 参数：

| 参数 | 类型 | 必填 | 兼容参数名 | 说明 |
| --- | --- | --- | --- | --- |
| `technician_id` | number | 是 | `technicianId` | 当前环节目标师傅 ID |
| `service_item_id` | number | 是 | `serviceItemId` | 服务环节 ID；重派时每一项都必须传 |
| `service_type` | string | 否 | `serviceType` | 一致性校验字段；如传入，必须与 `service_item_id` 对应的类型一致，不会修改环节类型 |

#### 3.3.2 整单重派可修改的资料参数

以下参数只用于整单重派。提交这些资料字段时必须省略 `service_item_id`、`assignments`。可以同时发送 `service_type`，后端会在同一事务内修改任务类型、任务资料和分派记录。

| 参数 | 类型 | 必填 | 兼容参数名 | 说明 |
| --- | --- | --- | --- | --- |
| `customer_name` | string | 否 | `customerName`、`name`、`customer.name` | 客户姓名；传入时不能为空 |
| `customer_mobile` | string | 否 | `customerMobile`、`mobile`、`phone`、`customer.mobile` | 客户手机号；传入时不能为空且不能与其他客户重复 |
| `customer_source` | string | 否 | `customerSource`、`customer.source` | 客户来源 |
| `address_id` | number | 否 | `addressId` | 当前客户已有地址 ID |
| `address` | string/object | 否 | `customer_address/customerAddress`、`service_address/serviceAddress`、`customer.address` | 新服务地址；优先于 `address_id` |
| `appointment_time` | string | 否 | `appointmentTime` | 预约时间，格式 `YYYY-MM-DD HH:mm:ss` |
| `service_time_slot` | string | 否 | `serviceTimeSlot` | 服务时段，例如“下午” |
| `priority` | string | 否 | 无 | 建议值：`low/normal/high` |
| `task_desc` | string | 否 | `taskDesc` | 任务描述；空字符串表示保存为空 |
| `task_remark` | string | 否 | `taskRemark` | 任务备注；空字符串表示保存为空 |
| `customer` | object | 否 | 无 | 兼容任务详情中的嵌套客户对象 |

`customer` 对象参数：

| 参数 | 类型 | 必填 | 兼容参数名 | 说明 |
| --- | --- | --- | --- | --- |
| `name` | string | 否 | `customer_name/customerName` | 客户姓名 |
| `mobile` | string | 否 | `customer_mobile/customerMobile/contact_phone/contactPhone/phone` | 客户手机号 |
| `source` | string | 否 | `customer_source/customerSource` | 客户来源 |
| `address` | string/object | 否 | `customer_address/customerAddress/service_address/serviceAddress` | 服务地址 |

地址对象参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `province` | string | 否 | 省 |
| `city` | string | 否 | 市 |
| `district` | string | 否 | 区县 |
| `detail` | string | 是 | 详细地址；兼容字段名 `address` |

#### 3.3.3 资料字段空值规则

| 输入形式 | 后端行为 |
| --- | --- |
| 字段未发送 | 保留原值 |
| 字段传 `null` | 与未发送相同，保留原值 |
| `assign_reason` 未发送、`null` 或空白 | 使用默认值“重新分派” |
| `service_type` 未发送 | 保留任务当前服务类型 |
| `service_type` 传空字符串、空白或非标准值 | 返回 400；不修改类型时请省略该字段 |
| `customer_name`、`customer_mobile` 传空白 | 返回 400 |
| `appointment_time` 传空白或格式错误 | 返回 400 |
| `address.detail/address` 传空白 | 返回 400 |
| `customer_source`、`service_time_slot`、`priority`、`task_desc`、`task_remark` 传空字符串 | 保存空字符串；其中空的 `service_time_slot` 回查时会回退为预约时间 `HH:mm` |

客户姓名、手机号、来源更新的是共享客户记录，该客户的其他历史任务再次查询时也会读取到新值。新地址与当前地址完全一致时复用当前地址；地址发生变化时才新增地址记录。

### 3.4 模式判断

| 模式 | 前端应发送的字段 | `service_type` 语义 | 是否允许修改任务资料 |
| --- | --- | --- | --- |
| 整单重派 | `technician_id` + 可选 `service_type` + 可选任务资料；省略 `service_item_id/assignments` | 新任务服务类型；未传则保留 | 是 |
| 单环节重派 | `technician_id` + `service_item_id` | 顶层可选，仅校验与环节 ID 一致 | 否 |
| 批量重派 | 非空 `assignments`，每项必须有 `service_item_id`；省略顶层 `technician_id/service_item_id/service_type` | `assignments[].service_type` 可选，仅作一致性校验 | 否 |

限制：

- `assignments` 不能为空。
- 同一个服务环节不能重复出现。
- 单环节和批量环节重派必须传 `service_item_id`，不能再只用 `service_type` 定位环节。
- `service_item_id` 或 `assignments` 与任务资料参数同时出现时返回 400。
- 顶层只传 `technician_id + service_type` 也属于整单重派，`service_type` 会修改当前任务本身。
- 修改任务类型要求当前任务恰好有 1 个服务环节。0 个或多个环节的历史异常任务只要显式传非空 `service_type` 就返回 409，即使传入值与当前类型相同；不修改类型时必须省略该字段。
- 同一 `task_group_no` 下已有目标服务类型时返回 409，避免同批任务出现重复类型。
- 显式传 `service_type` 时，目标师傅必须具备新类型能力；未传时必须具备任务全部当前环节能力。可选择当前同一位师傅。
- 类型、任务资料、分派记录、任务主表和唯一服务环节在同一事务内更新，任一步失败全部回滚。

前端整单重派表单中的任务类型必须是单选字符串，不是数组：

```ts
type ServiceType = 'measure' | 'install' | 'ironing' | 'cleaning';

type WholeReassignPayload = {
  technician_id: number;
  service_type?: ServiceType;
  assign_reason?: string;
  appointment_time?: string;
  service_time_slot?: string;
  priority?: string;
  task_desc?: string;
  task_remark?: string;
};
```

打开弹窗时用详情 `data.service_type` 初始化单选值；用户切换类型后，师傅列表应按新值重新请求 `GET /api/technicians/available?store_id={storeId}&service_type={serviceType}`。

### 3.5 整单重派请求示例

允许重新分派给当前同一位师傅：

```json
{
  "technician_id": 29,
  "service_type": "install",
  "assign_reason": "任务资料调整后重新分派",
  "customer_name": "张三",
  "customer_mobile": "13800000000",
  "customer_source": "门店到访",
  "appointment_time": "2026-07-18 14:30:00",
  "service_time_slot": "下午",
  "address": {
    "province": "浙江省",
    "city": "杭州市",
    "district": "西湖区",
    "detail": "文一路 123 号"
  },
  "priority": "normal",
  "task_desc": "更新后的任务描述",
  "task_remark": "更新后的备注"
}
```

例如原任务为 `measure`，以上请求成功后当前任务会变为 `install`。后端同步更新 `task.service_type` 和唯一的 `task_service_item.service_type`；数据库字段 `task_type` 不参与本次修改。

未发送的资料字段保留原值。新地址会新增为客户地址并绑定当前任务，不会覆盖旧地址。

### 3.6 单环节请求示例

```json
{
  "service_item_id": 101,
  "technician_id": 29,
  "assign_reason": "安装环节重新安排"
}
```

### 3.7 批量请求示例

```json
{
  "assignments": [
    {
      "service_item_id": 101,
      "technician_id": 29
    },
    {
      "service_item_id": 102,
      "service_type": "ironing",
      "technician_id": 30
    }
  ],
  "assign_reason": "按服务能力重新安排"
}
```

### 3.8 成功响应参数

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `task_id` | number | URL 对应的任务 ID |
| `task_status` | string | 重派后的任务状态，通常为 `pending_execute`，部分环节重派后可能为 `executing` |
| `service_item_id` | number/null | 一次只命中一个环节时返回环节 ID；整单或多个目标时为 `null` |
| `service_type` | string/null | 整单请求显式传了合法非空 `service_type` 时返回该值，即使值未变化；单环节时返回命中环节类型；未传类型的整单或多个目标时为 `null` |
| `execution_id` | null | 重派接口不会创建新执行记录，固定为 `null`；本次受影响环节的旧活动执行不能继续使用 |

成功响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "task_id": 1001,
    "task_status": "pending_execute",
    "service_item_id": null,
    "service_type": "install",
    "execution_id": null
  },
  "request_id": "uuid"
}
```

### 3.9 类型变更后的数据规则

整单重派成功后：

| 数据 | 处理结果 |
| --- | --- |
| `task.service_type` | 更新为请求中的新类型 |
| 唯一 `task_service_item.service_type` | 同步更新为新类型 |
| `task.current_technician_id`、环节 `technician_id` | 更新为目标师傅；允许与原师傅相同 |
| 任务和环节状态 | 重置为 `pending_execute` |
| 环节开始/完成时间、进度 | 清空开始/完成时间，进度重置为 0 |
| `task.latest_execution_id` | 清空 |
| 旧 `executing` 执行记录 | 改为 `cancelled`，不能继续提交 |
| 旧执行记录的 `service_type` | 保留旧类型，用于历史追溯 |
| 旧执行记录的 `service_item_id` | 类型发生变化时置为 `null`，避免旧执行被识别成新类型环节 |

任务或任一环节已经进入提交检核、待评价、待评分、已完成或已关闭流程时不允许重派，返回 409。

### 3.10 前端保存成功后的处理

`POST /reassign` 不返回完整任务资料。成功后前端必须：

1. 清除本次重派范围内的旧 `execution_id`；整单重派时清除当前任务全部旧执行 ID。
2. 调用 `GET /api/tasks/{id}` 或 `GET /api/tasks/{id}/detail`。
3. 重新请求任务列表和顶部统计。

### 3.11 重派常见错误

| HTTP/业务码 | `message` 示例 | 触发条件 | 前端处理 |
| --- | --- | --- | --- |
| `400 / 1001` | `service_type不能为空；不修改任务类型时请省略该字段` | 显式传空类型 | 不修改时删除请求字段 |
| `400 / 1001` | `service_type仅支持measure/install/ironing/cleaning` | 类型值不合法 | 只提交标准英文编码 |
| `400 / 1001` | `按服务环节重派时 service_item_id 不能为空` | 单环节模式没有环节 ID | 使用详情 `service_items[].id` |
| `400 / 1001` | `按服务环节重派时 assignments[].service_item_id 不能为空` | 批量项缺少环节 ID | 为每一项补齐 ID |
| `400 / 1001` | `批量重派时请省略顶层technician_id、service_item_id和service_type` | 批量请求夹带会被忽略的顶层分派字段 | 只保留 `assignments` 和 `assign_reason` |
| `400 / 1001` | `service_type与service_item_id不匹配，请刷新后重试` | ID 和可选类型不一致 | 刷新详情后重建表单 |
| `409 / 2002` | `修改任务类型要求当前任务且仅有一个服务环节` | 当前任务没有环节或包含多个环节 | 不发送新类型，或先修复任务环节数据 |
| `409 / 2002` | `同一批任务中已存在该服务类型，不能重复修改` | 同组已有目标类型 | 选择同组尚不存在的类型 |
| `409 / 2002` | `所选技师不具备...服务能力` | 师傅没有新类型能力 | 按新类型重新筛选师傅 |
| `409 / 2002` | `当前任务状态不允许重派技师` | 状态不是待执行/执行中 | 刷新详情并关闭重派弹窗 |
| `409 / 2002` | `任务已提交检核，不能再重派` | 已有提交记录 | 禁止继续重派 |

## 四、任务详情回查接口

### 4.1 接口信息

```http
GET /api/tasks/{id}
```

兼容地址：

```http
GET /api/tasks/{id}/detail
```

### 4.2 路径参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | number | 是 | 任务 ID |

### 4.3 查询参数

| 参数 | 类型 | 必填 | 兼容参数名 | 说明 |
| --- | --- | --- | --- | --- |
| `service_item_id` | number | 否 | `serviceItemId` | 只查询指定服务环节详情 |
| `service_type` | string | 否 | `serviceType` | 按服务类型查询环节详情 |

### 4.4 本次需要回读的响应参数

| 参数路径 | 类型 | 说明 |
| --- | --- | --- |
| `data.service_type` | string | 当前任务保存后的服务类型；类型变更成功后应等于请求中的新值 |
| `data.task_status` | string | 最新任务状态 |
| `data.priority` | string | 优先级 |
| `data.appointment_time` | string/null | 最新预约时间 |
| `data.service_time_slot` | string/null | 保存的服务时段；无保存值时回退为预约时间 `HH:mm` |
| `data.task_desc` | string/null | 任务描述 |
| `data.task_remark` | string/null | 任务备注 |
| `data.customer_source` | string/null | 客户来源 |
| `data.address_id` | number/null | 当前服务地址 ID |
| `data.customer_address` | string | 完整服务地址文本 |
| `data.customer.name` | string | 客户姓名 |
| `data.customer.mobile` | string | 客户手机号 |
| `data.customer.source` | string/null | 客户来源兼容字段 |
| `data.customer.address_id` | number/null | 地址 ID 兼容字段 |
| `data.customer.address` | string/null | 地址文本 |
| `data.technician` | object/null | 当前师傅信息 |
| `data.service_items` | object[] | 服务环节及各环节师傅、状态、排期；正常单选任务长度为 1 |
| `data.service_items[].id` | number | 服务环节 ID，单环节/批量重派时必须回传此值 |
| `data.service_items[].service_type` | string | 环节保存后的服务类型；单环节任务整单改类型后与 `data.service_type` 一致 |
| `data.service_items[].service_status` | string | 整单重派时全部重置为 `pending_execute`；环节重派时只重置选中环节 |
| `data.service_items[].technician_id` | number/null | 环节当前师傅 ID |
| `data.service_items[].scheduled_time` | string/null | 环节排期；整单修改预约时间时同步更新 |
| `data.service_items[].started_at` | string/null | 整单重派时全部清空；环节重派时只清空选中环节 |
| `data.service_items[].completed_at` | string/null | 整单重派时全部清空；环节重派时只清空选中环节 |
| `data.service_items[].progress_percent` | number | 整单重派时全部重置为 `0`；环节重派时只重置选中环节 |
| `data.executions` | object[] | 当前任务全部执行历史，包含已取消的旧类型记录 |
| `data.executions[].id` | number | 执行记录 ID |
| `data.executions[].service_item_id` | number/null | 当前环节关联 ID；类型变更前的旧执行会变为 `null` |
| `data.executions[].service_type` | string/null | 该次执行发生时的服务类型；旧记录保留旧值 |
| `data.executions[].technician_id` | number | 该次执行的师傅 ID |

| `data.executions[].started_at` | string/null | 该次执行开始时间 |
| `data.executions[].submitted_at` | string/null | 该次执行提交时间；已提交的任务不允许重派 |
| `data.evidence_count` | number | 当前任务全部历史实据数量 |
| `data.evidence_items` | object[] | 当前任务全部实据历史 |

## 九、前端必须注意

1. 师傅完整表单必须稳定发送 `name/mobile/store_id/service_types/status`。
2. 门店完整表单必须稳定发送 `store_name/province/city/district`。
3. 清空字段后可以省略，但必须确保请求满足对应完整表单识别条件。
4. 局部 PATCH 中字段未发送表示保留，清空请发送 `null` 或空字符串。
5. 后端返回的 `null` 是新值，不能使用 `|| oldValue` 或 `?? oldValue` 回填旧数据。
6. 重派成功后必须重新请求任务详情；师傅和门店可直接使用 PATCH 返回的完整 `data`。
7. 整单修改任务类型时只传顶层 `service_type`；单环节/批量重派必须传 `service_item_id`。
8. 师傅下拉列表必须按重派表单当前选中的新 `service_type` 过滤，不能继续按旧任务类型过滤。

## 十、数据库说明

本次师傅、门店清空规则和任务重派类型修改没有新增数据库字段，**不需要新建或执行额外迁移**。

任务类型修改复用现有字段。部署环境应已按历史顺序应用：

- `migrations/0013_task_execution_service_item.sql`：执行记录的 `service_item_id/service_type`。
- `migrations/0017_task_group_no.sql`：任务分组号 `task_group_no`。

如果生产库已经执行到当前最新迁移，无需做任何表结构变更。

如果当前环境尚未应用客户手机号唯一索引，并且要支持重派时修改客户手机号，需要执行：

```text
migrations/0025_customer_mobile_unique.sql
```

执行前先检查重复手机号：

```sql
SELECT mobile, COUNT(*) AS total
FROM customer
GROUP BY mobile
HAVING COUNT(*) > 1;
```

存在重复时先合并客户及其关联数据，再执行迁移。
