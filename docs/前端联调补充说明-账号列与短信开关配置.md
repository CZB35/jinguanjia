## 适用范围

本说明只覆盖两项最近联调变更：

- 权限管理列表里的“账号”列
- 平台级短信开关配置

所有接口默认都挂在 `/api` 下。

## 1. 权限管理列表“账号”列

接口：

```http
GET /users
```

### 当前变化

后端列表项里新增字段：

```json
account
```

示例：

```json
{
  "id": 1,
  "name": "admin",
  "account": "admin",
  "mobile": "admin"
}
```

### 前端接法

权限管理列表里：

- “姓名”列 -> `name`
- “账号”列 -> `account`
- “管理员电话”列 -> `mobile`

不要再让“账号”列显示 `--`，直接使用后端返回的 `account`。

## 2. 平台级短信开关配置

当前后端增加了两个平台级配置开关，配置位置都在 `system_config`。

### 开关 1：经销商短信通知

配置键：

```text
sms.switch.dealer_notify
```

用途：

- 控制“经销商评分通知短信”是否发送

### 开关 2：客户评价短信通知

配置键：

```text
sms.switch.customer_review
```

用途：

- 控制“客户评价短信”是否发送

### 值说明

支持：

```text
true
false
```

默认行为：

- 不配置时，后端按 `true` 处理
- 配成 `false` 时，平台层面直接不发短信

## 3. 前端配置方式

现有系统配置接口：

```http
GET /system/configs
PATCH /system/configs
```

### 展示建议

基础信息里新增一个菜单：

```text
短信开关配置
```

页面建议展示两项：

- 经销商短信通知
- 客户评价短信通知

每项一个开关。

### 保存请求示例

```json
{
  "items": [
    {
      "config_key": "sms.switch.dealer_notify",
      "config_value": "true",
      "remark": "经销商短信通知开关"
    },
    {
      "config_key": "sms.switch.customer_review",
      "config_value": "false",
      "remark": "客户评价短信通知开关"
    }
  ]
}
```

## 4. 说明

短信最终是否发送，现在有两层控制：

1. 平台级开关：`sms.switch.*`
2. 用户级开关：`user_message_setting.sms_enabled`

只要平台级开关是 `false`，后端就不会发送对应短信。
